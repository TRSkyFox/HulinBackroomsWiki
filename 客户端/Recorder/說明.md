# 狐霖的后室 RPG — 画面文字记录器（Wiki 版）

> **2026-11-04 注意**：这份是旧自动 OCR 记录器（`backroom-logger.ps1`）的手册，部分指令与 exe 名称已过时。现行人工记录器（Q／E、六种模式）请看根目录 `README.md` 与 `客户端/README.md`。

把游戏里出现过的每一段文字，自动认成**结构化的 wiki 素材**存下来 ——
楼层、场景、旁白、决定、选项、掷骰、状态变化、道具、队伍频道全部分开标记，
**可以直接丢给 AI 整理成 wiki**。只留文字、截图用完即删，在背景跑不干扰你玩。

> **2026-10-16 这版加了一堆“认得更准”的机制**：OCR 前放大、分区 OCR、
> 楼层配色自动记录、OCR 错字自动修正、三种特殊版面自动判断。
> **日常玩法完全没变**：双击 `BackroomLogger.exe`、按开始，就这样。
> 只有想调细节（或不想让它动你的窗口）才需要看下面的〈命令列〉。

---

## 为什么是“看画面”

这个游戏是 **Unity WebGL**：所有文字都画在一张 `<canvas>` 上，DOM 和无障碍树里
**一个字都没有**（实际查过，只有 10 个空的图片节点）。所以只能看画面：

```
背景截图 → 只裁游戏画面 → Windows 内建 OCR（不连网）→ 分类 → 图立刻删掉 → 写成 wiki
```

2026-10-16 之后，中间那步“OCR”变得讲究多了（放大、分区、修正），
但**整条路一样是“看画面”**，没有变成读网页源代码那种做法。

## 用法

双击 **`BackroomLogger.exe`**，一颗按钮：

| 控制 | 作用 |
|---|---|
| **▶ 开始记录 / ■ 停止记录** | 同一颗切换（停止是优雅的：会删暂存图、写完最后一笔才结束） |
| **每 N 秒抓一张** | 想抓更细就调 1 秒 |
| **☐ 保留截图** | 平常不用勾 |
| **开启 wiki.md** | 打开这一场的成果 |
| **重建／合并 Wiki** | 把所有场次重新整理成 `wiki-all.md` + `INDEX.md`（不删东西，可放心多按） |
| **收工：导出最新补充，然后清空 logs** | ⭐ **只导出“上次之后的新内容”**成一个 `.md` 放在 exe 旁边，然后清空 logs —— 另一个 agent 每次只读新增的部分 |
| 状态列 | 即时显示跑了多久、已收几个事件 |

### ⚠ 小窗口只会用“默认值”跑

`BackroomLogger.exe` 是 **2026-10-14 编的**，它只会传 `-Interval`、`-SaveFrames`、
`-StopFile`、`-WikiAll`、`-Export` 这几个旧参数。**10-16 的新功能它一颗开关都没有**，
所以双击 EXE ＝ 用默认值跑，其中两个默认值会直接影响你：

| 默认行为 | 你会看到的 |
|---|---|
| **开录前把游戏窗口改成 `2091x1297`（位置不动）** | 窗口尺寸被改掉；**位置不会被搬动** |
| OCR 放大 1.25 倍、分区 OCR、OCR 错字修正：**三个都默认开** | 认得更准，但你会发现 wiki 的字变干净了 |

**不想被搬窗口**（例如正在用大屏幕、或想边玩边做别的事）：

```powershell
.\backroom-logger.ps1 -WinPos ''      # 只改尺寸，位置不动
.\backroom-logger.ps1 -NoResize       # 尺寸位置都不动
```

改窗口大小是**不抢焦点**的（用 `SetWindowPos` ＋ `SWP_NOACTIVATE|SWP_NOZORDER`），
不会把你从别的窗口踢走；改完还会**等 2.5 秒**让 Unity 重新排版再开始抓。

## OCR 怎么认得更准（2026-10-16 新增）

### 1. 先放大再认：`-OcrScale`（默认 `1.25`）

Windows OCR 对这种小字＋像素风字体很吃力，常见的错法是**把一个中文字拆成部首**。
把图放大再送 OCR 就修好了，但**放大过头反而更糟**：

| 倍数 | 结果 |
|---|---|
| `1`（＝关掉） | 原样，`你`容易被读成`亻尔`、`前任`→`甫亻壬` |
| **`1.25`（默认，实测最佳）** | 部首拆解修好（`亻尔`→`你`、`甫亻壬`→`前任`），**又不会**把 `Level` 读成 `LeveI` |
| `2` 以上 | **过头**：连 `Level` 都被读成 `LeveI`，整体变差 |

放大是用高质量双三次内插（`HighQualityBicubic`），而且**裁切一定在放大之前**
（坐标是原图的，放大后才不会对不上）。

### 2. 分区 OCR：一次只看四个区块（默认开，`-NoRegion` 关掉）

**为什么要分区**：整窗 OCR 会把画面上所有字一起吃进来，包括右上角的按钮列
（`催促`、`背包 (B)`、`离开`）和右侧的队伍频道聊天（`跟我走！`、`哈哈`），
这些**界面与聊天文字会混进 wiki 正文**，事后要靠关键字一条一条滤，很容易漏。

分区之后，OCR 只看这四块（实测**杂讯归零**：`催促／背包 (B)／离开／跟我走！／哈哈／送出`
等 10 个词在分区模式下**出现 0 次**）：

| 区块 | 默认坐标 `x0,x1,y0,y1` | 内容 |
|---|---|---|
| `title` | `10,1330,0,88` | `Level N「名稱」` ＋ `第 N 層 \| 難度 \| 區域` |
| `main` | `25,1330,100,776` | **主文字面板：故事全文（OCR 主力）** |
| `opts` | `25,1330,783,1185` | `要走哪条路？`／`要怎么做？` ＋ 选项 |
| `char` | `1155,1700,88,200` | 角色卡（名字／Lv／职业／HP／MP）—— **整区都是界面，不记事件** |

- 坐标是 **render 区（实际送 OCR 的那张图）的像素**，校正基准 `2067x1205`；
  实际 render 区尺寸不一样时会**自动等比缩放**。
- **`-RegionMinLines`（默认 `5`）**：分区加起来不到 5 行、或某一区 OCR 失败
  → **自动退回整张 OCR**，并在 `logger.log` 记一笔警告（那一帧的行首标记会变成 `[full]`）。
  所以“画面怪怪的”不会直接变成一堆空资料。
- **`-NoRegion`**：整层关掉，回到以前的整张 OCR。
- **`-AutoRegion`（默认关）**：开启时，本帧若量到跟参数差超过 10px 的新边界，
  **这一帧就直接用新边界**——只存在记忆体，**不改参数、不改任何文件**。

### 3. `ocr-raw.log` 多了“区块标记”

以前 `ocr-raw.log` 只有一行行文字，现在每一行前面会标**它是从哪一区来的**，
每一帧的标头也会写**配色**与**版面**：

```
[2026-10-16 07:04:32] 原始 OCR 逐帧记录（完整保留，未经过滤）
===== 2026-10-16 07:04:35 帧 #1 2067x1205 (OCR 2067x1205) 配色=#2E2813 版面=normal 行数=21 =====
[title] Level 0 “大厅”
[title] 等大家决定一
[main] 回过神来，你已经摔在一片湿湿的地毯上。……
```

| 标记 | 意思 |
|---|---|
| `[title]` / `[main]` / `[opts]` / `[char]` | 分区 OCR 的来源区块 |
| `[full]` | 这一帧走**整张 OCR**（特殊版面，或分区退回） |
| `[item]` | 背包面板里的物品／属性行（方便事后挑出来） |
| 帧标头 `配色=#RRGGBB` | 这一帧在 `main` 区取样到的面板底色 |
| 帧标头 `版面=normal\|backpack\|ending\|panel` | 这一帧被判断成哪种版面 |

怀疑 OCR 认错字、或想知道“这行是哪来的”，**就是回来查这个档**。

### 4. 楼层配色自动记录

每一帧都在 `main` 区右上角**没有文字的一小块**取样平均色（大小＝`-ColorSample`，
默认 `48` 像素方块，往内缩 40px 避开文字）。底色变化超过 **`-ColorThreshold`（默认 `24`）**
就写一笔到 `floor-colors.log`（楼层名从 `title` 区 OCR 抓）：

```
[2026-10-16 07:04:32] 各楼层界面配色（自动检测；底色变化超过 24 就记一笔）
2026-10-16 07:04:35  #2E2813  rgb(46,40,19)  Level 0 “大厅”  帧#1
```

同一份配色也会**累积**到 exe 旁边的 **`floor-colors-cache.json`**：

- 种子＝ `backroom-wiki\_data\_floor-colors.md` 的**人工实测配色表**（那张表最高权威，
  **实测值永不被自动值覆盖**）。
- 之后由每一场的 `floor-colors.log` 自动累积（楼层 → 底色、出现次数、来源）。
- 同一层出现不同色（换区域、弹窗底色）→ 主色不动，新的色码记进 `alt` 让人看。
- 这个快取同时是“自动校正分区”的依据：每帧先用底色比对“最接近哪一层”，
  拿该层的预期底色当扫描种子色。**没快取、或色差超过门槛**才会做全图扫描
  （同一层一次、至少间隔 4 秒），所以不会拖慢每一帧。

配色也会**写进输出**（只新增字段，不动既有格式）：
`wiki.md` 的楼层段落后面多一行 `<!-- color:#RRGGBB -->`，
`wiki.jsonl` 的楼层事件多一个 `color` 字段。

**同步回 Wiki**：`D:\Project\HulinBackroomsWiki\wiki\sync-floor-colors.ps1`
会把各场 `floor-colors.log` 并进 `_data\_floor-colors.md` 的配色表
（先加 `-WhatIf` 看它打算加什么）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sync-floor-colors.ps1 -WhatIf
powershell -NoProfile -ExecutionPolicy Bypass -File .\sync-floor-colors.ps1
```

它**只读** log、**只写**那张表；新楼层新增一列，同层不同色**不覆盖原列**，
而是另外加一列标成“冲突”等人裁决，重复执行也安全。

### 5. OCR 错字修正（默认开，`-NoOcrFix` 关掉）

Windows OCR 对这个游戏有**固定且会重复发生**的误读。与其每次事后人工比对，
现在在“正规化（清空白）”之后多套一层规则表，把**确定不会误伤**的误读修回来。

- 规则表在 `backroom-logger.ps1` 上方的 **`$script:OcrFixRules`**（共 11 条）。
- **资料驱动**：每条写成 `@(类型, 样式, 取代值, 说明)`
  - `'x'` ＝固定字串取代
  - `'r'` ＝规则运算式（全部取代）
  - `'r1'`＝规则运算式，只换第一笔
  - 执行顺序＝数组顺序（上面的先跑），所以**有相依的规则顺序不能颠倒**
- **要调就直接改那张表**（停用某条：在它前面加 `#` 或整条删掉）。
  每条旁边都有注解写“为什么这样改是安全的”。
- **`-NoOcrFix`** 可以整层关掉（正规化、分类都不受影响）。

已经处理的误读（节录）：

| 误读 | 修正 | 为什么安全 |
|---|---|---|
| `刁吣！`／`刂吣！`／`刁 № 心！` | `小心！` | 只认**整行**就是这几个字形组合（快速聊天钮），正文不会整行只有这些 |
| `亻尔` / `甫亻壬` | `你` / `前任` | 部首被拆开的组合，正常中文不会出现（`甫亻壬` 那条要排在 `亻尔` 前面） |
| `LeveI` / `Leve1` / `Leve15` | `Level` / `Level5` | 两条规则、顺序不能反：先处理“`leve1` 后面接数字”，再处理剩下的 |
| `理智．1`（`體力·2` 这类） | `理智 -1` | 只在“**已知状态名** ＋ 分隔符 ＋ 一位数字（后面不是数字）”时换 |
| `〔…〕`／`〖…〗` | `【…】` | 只换“整行就是一组外框”的场景标题 |
| `第 2 层《岔路` | `第 2 层 \| 岔路` | 只作用在“第 N 层”开头的标题行 |
| `徒出了这”层` | `走出了这一层` | 只认这个固定短语，且**没有锚定行尾**（OCR 常把它跟后半句黏成一行） |
| 数字中间的 `．`／`·` | `.` | 只在“数字．数字”时换，句尾的 `。` 不受影响 |

**这是保守设计**：实测 22 条样本里，13 条真的误读被修正、**9 条正常文字完全没被动到**。
`-NoOcrFix` 之下 22 条原样不变、一个字都没改。

### 6. 三种特殊版面：背包／结局／弹窗

分区坐标**只对“标准游玩画面”有效**。这三种版面会整个盖掉标准版面，
硬套分区会把大段文字切掉，所以：

| 版面 | 怎么认 | 结果 |
|---|---|---|
| `backpack`（背包与装备） | 出现“背包与装备／装备栏”之类字样 | 改用整张 OCR，物品／属性行**另外标 `[item]`** |
| `ending`（全屏幕结局） | **整片近黑**（中央大半取样区 90% 以上亮度 < 40），或出现“跳过” | 改用整张 OCR |
| `panel`（弹窗三栏面板） | 出现“编号／雕刻／门后”，或“任务＋目标”这种字段名 | 改用整张 OCR |

做法是**两段检测**：

1. **便宜预检**：只 OCR 标题列那一小条（约 1300x88）。标准画面的标题列一定有
   `Level N「…」`，**看不到就代表不是标准画面** → 改用整张 OCR。
   （只多花一次小区块 OCR，不是每帧都整张 OCR 两次。）
2. 整张 OCR 之后再依**文字特征**分背包／三栏面板、依**颜色**分结局。

特殊版面时 **`title`／`opts`／`char` 三个分区不套用**（才不会把大段文字切掉），
那一帧的行首标记是 `[full]`，帧标头写 `版面=…`，`logger.log` 也会记一笔版面变化。

### 7. 窗口尺寸锁定：`-WinSize` / `-WinPos` / `-NoResize`

分区坐标是**固定像素**，所以**窗口尺寸是分区裁切的前提**——
窗口一变大变小，坐标就跑掉了。因此开录前会先：

```
-WinSize 2091x1297  -WinPos （空）    →   SetWindowPos（不抢焦点、不改 Z 序）
```

- `-WinSize`：`寬x高`（**含浏览器外框**），默认 `2091x1297`。
- `-WinPos`：**默认 `right` ＝ 贴齐屏幕右缘（保留尺寸）**。其他关键字：`topright`／`left`／`center`／`splitright`／`splitleft`（后两者是 Windows 真正的半屏幕贴靠，**会改变尺寸 → 需要重新 `-Calibrate`**）；也可直接给 `x,y`；留空 = 完全不动位置。
- `-NoResize`：**完全不动**窗口（适合你已经自己排好版面、或不想被搬）。
- 屏幕放不下时会被系统夹住，工具列会印出“实际 WxH，要求 WxH”提醒你。

## 换了环境就要重新校正：`-Calibrate`

**什么时候要重跑**（任何一个变了就要）：

- 换**楼层配色**（不同楼层面板底色不一样）
- 换**浏览器缩放**（不是 100% 时比例会变）
- 换 **`-WinSize`**（或改过窗口大小）
- 换**屏幕／分辨率**

跑法（**不录影、不会动你的窗口**）：

```powershell
# 直接看现在的游戏窗口
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Calibrate

# 或 用一张现成的图档（图必须是 render 区尺寸）
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -CalibrateImage 'C:\Users\HX\Desktop\后室RPG-参考截图\_即时frame_2067x1205.jpg'
```

它会印出：

1. **量到的面板**：`main`／`opts` 的底色、取样点、上下界与左右界、空白分隔带
2. **用目前参数试跑一次分区 OCR**：每一区抓到几行、前 10 行长什么样
   （**这步最重要**：看得到内容才代表坐标对）
3. **楼层配色快取比对**：检测到哪一层、取样色 vs 快取预期色、是否一致
4. **与目前参数比较**：差 **>10px** 就标 ⚠（只警告“量到比默认窄”，因为量到更宽
   可能只是把同色的隔壁面板算进来）
5. **可直接复制的新参数**：一行 `-RegionTitle '…' -RegionMain '…' -RegionOpts '…' -RegionChar '…'`

校正完也会把量到的边界写进 `floor-colors-cache.json`（录影时就直接用得到）。

> **坐标的依据存在 `D:\Project\HulinBackroomsWiki\wiki\_drafts\截圖分區座標.md`**
> —— 里面有校正基准（屏幕 / 窗口外框 / render 区尺寸）、每个区块的坐标与说明、
> 以及量测依据（逐栏逐列的底色命中率）与量测脚本。
> **改动窗口大小或浏览器缩放时，那份要重写。**

## 输出格式（给 AI 用的）

每场次一个文件夹 `logs\backroom-YYYYMMDD-HHMMSS\`：

| 文件 | 内容 |
|---|---|
| **`wiki.md`** | ⭐ 主要成果：结构化逐字稿，AI 可以直接拿去写 wiki |
| `wiki.jsonl` | 同一份资料的事件流（一行一事件，有型别），要精确处理时用 |
| `ocr-raw.log` | **未过滤**的原始 OCR 全文（每帧都留）。每行前面有 `[区块名]`、帧标头有 `配色=`／`版面=` —— 怀疑 OCR 认错字、或想知道某行怎么来的就查这里 |
| `floor-colors.log` | 这一场量到的**各楼层界面配色**（底色变化超过门槛就记一笔） |
| `logger.log` | 程序自己的运行记录（含分区退回、版面变化、自动校正扫描、建议坐标） |
| `frames\` | 只有加 `-SaveFrames` 才会有；默认不留截图 |

`wiki.md` 长这样：

```markdown
## Level 0 “大厅”
<!-- color:#302810 -->

### 〖开场的铃声〕
@ 08:10:37
N 单调的黄色壁纸、潮湿的地毯、到处都是的电源插座，还有头顶那永远不会停的日光灯嗡嗡声。
D 你决定：“往传来“叮——”的一声的方向走”
O 跟着铃声的节奏，带你往前走（魅力 难度11）｜捂住耳朵，快走
Q 天狐：跟我走！
C 魅力 难度11 天狐 · 魅力检定 · 难度 11
R 魅力 难度11 天狐 5+5=10 失败
S 天狐：理智 -2、口渴 +1
I 天狐：得到“急救毯”
```

### 标记对照

| 标记 | 意思 | 为什么对 AI 有用 |
|---|---|---|
| `##` / `###` | 楼层 / 场景 | 直接就是 wiki 的页面与段落标题 |
| `<!-- color:#RRGGBB -->` | 这层的界面配色 | 对照 Wiki 的配色表（10-16 新增） |
| `@ 時:分:秒` | 时间 | 只在跨分钟或间隔 >15 秒时标，省 token 又保留时间轴 |
| `N` | 旁白 | wiki 的正文 |
| `D` | 决定 | 玩家做了什么选择 |
| `O` | 选项（含检定难度） | 选项树、每个选项要骰什么 |
| `R` | 掷骰结果 | `技能 難度 誰 骰值=總值 成功/失敗`（字段化） |
| `C` | 检定宣告 | 即将进行的检定 |
| `S` | 状态变化 | 体力/理智/口渴/经验/出口进度 |
| `I` | 道具 | 得到、捡起 |
| `Q` | 队伍频道 | 队友对话 |
| `>` | 记录中断 | 什么时候切走了分页、暂停多久 |

### 为了“省”做的事

- **同一段旁白合并成一行**（OCR 常把一段话切成两三行）
- **界面杂讯不记**：按钮、提示文字、快捷聊天钮、`已决定`、`思考中` 之类全部滤掉 ——
  现在有**两层防线**：先靠**分区 OCR** 从源头不看那些区块，再靠关键字清单补刀
- **角色卡不记事件**：`char` 区整区都是界面（名字／Lv／职业／HP／MP），整区不进 wiki
- **同一句话不重复收**（含模糊比对；游戏重绘画面时不会灌爆）
- **半截片段不收**：已经有更完整的同一句时，短的残缺版会被丢掉
- **时间只在需要时标**，其他全靠顺序
- **截图不留**：OCR 完立刻删，跑好几小时也只有几百 KB

## 两种收尾方式

### 1. 重建／合并 Wiki（不删东西）

按“重建／合并 Wiki”或命令列 `-WikiAll`：

| 文件 | 内容 |
|---|---|
| `logs\wiki-all.md` | 所有场次按时间合并成**一份**，AI 整理 wiki 的单一入口 |
| `logs\INDEX.md` | 场次索引：每场的开始时间、事件数、走过的楼层 |

各场次的 `wiki.md` 也会顺便重新整理。同一个事件流重跑几次结果都一样（幂等），可以放心多按。

### 2. 收工：导出“最新补充”，然后清空（⭐ 要拖给 AI 用这个）

按 **“收工”**（或命令列 `-Export`）会先停掉记录器，然后在 **exe 旁边生成两个文件**，
最后删掉 `logs` 底下所有场次文件夹：

| 文件 | 大小 | 用途 |
|---|---|---|
| **`backroom-summary-*.md`** | 小（实测 2.45 MB 的记录 → **88 KB**，其中 ① 摘要只有 350 行 / 1.3 万字元） | ⭐ **拖这个给 AI** |
| `backroom-update-*.md` | 大（约原始的 60%，已去重去杂讯但不截断） | 留著当 **wiki 出处**的依据 |

### 为什么读起来快很多

导出时会做四件事（实测在同一份 2.45 MB 记录上）：

| 处理 | 效果 |
|---|---|
| 全域去重（不只比最近 240 行） | 去掉 **45%** 完全重复的行 |
| 去掉 OCR 碎裂杂讯（符号比中文多的行、太短的碎片） | 再去掉一大批 `墨 / 」、｜司吊月豕只…` 这种垃圾 |
| 楼层／场景标题只在“变了”的时候留一次 | 去掉 3,000 多个重复标题 |
| `C` 检定宣告 + 紧接的 `R` 掷骰结果 → 合并 | 少一半重复信息 |

`backroom-summary-*.md` 的结构：

```
① 快速摘要（约 350 行，先读这段通常就够）
   走过的楼层 / 场景（含所属楼层）/ 这次拿到的道具
   检定掷骰汇总（各技能难度的成功失败次数、骰值例）
   出现过的选项（去重）/ 机制关键句（含技能、伤害、状态、效果…）
   每个场景代表句（最长的一句，快速抓到发生什么）
② 重点事件（结构化事件全留、旁白只留 ≥20 字的、不含队伍频道、各段有笔数上限）
   —— 被上限省略的笔数会列出来，完整内容指向完整档
```

**阅读量：** 原始 99 万字元 → ① 摘要 1.3 万字元 = **约 78 倍快**。

**关键：不会每次重写全部历史。** 导出到哪会记在 `export-state.json`（隐藏档），
下次只拿新的部分 —— 另一个 agent 每次只要读那一小份补充。

- 同一场玩到一半按“收工”，下次也只会拿到那场之后新增的事件（不会重复）
- 上次之后没有新东西 → 不会生成文件，直接告诉你“还没有新内容”
- 想忽略记录、**完整**重汇一次：`-Export -ExportAll`
- 完整档（`backroom-update-*.md`）是 wiki 出处的唯一依据，**别删**；建议复制到 `backroom-wiki\來源紀錄\`

> 想留底：删掉之前把 `logs` 整个文件夹复制一份就好。
> 场次还在录影中不会被导出（会提示你先停止），所以不会删到正在写的文件。
> ⚠ 收工会清掉 `logs`，所以**收工前先跑一次 `sync-floor-colors.ps1`**，
> 免得这几场量到的楼层配色还没并进 Wiki 就被清掉了。

## 命令列（一般用不到）

```powershell
# 平常（照默认值：窗口固定成 2091x1297 并贴齐屏幕右缘，分区＋放大＋错字修正都开）
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1

# 只抓一张测试（最安全，不录影、不建场次）
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Once

# 不想被搬窗口
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -WinPos ''
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -NoResize

# 每秒一张 / 重建合并 / 收工
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Interval 1
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -WikiAll
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Export

# 换了缩放或楼层配色，重新校正分区坐标
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Calibrate
```

### 参数一览（实际默认值以这份为准）

**基本**

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Interval` | `2.0` | 每隔几秒抓一张 |
| `-OutDir` | `.\logs` | 输出文件夹 |
| `-Language` | `zh-Hans-CN` | OCR 语言（另有 `en-US`） |
| `-Hwnd` | `0`（自动找） | 直接指定窗口代码 |
| `-TitleMatch` | `後室\|Backrooms\|狐霖\|hulin` | 用窗口标题找游戏 |
| `-Once` | — | 只抓一张、印出结果就结束（测试用） |
| `-Quiet` | 关 | 不要在主控台印每一行 |
| `-SaveFrames` | 关 | 保留截图当证据（默认删） |
| `-KeepFrames` | `200` | 只有 `-SaveFrames` 时有用 |
| `-StopFile` | 无 | 出现这个文件就收工（EXE 的停止钮用） |

**认得更准（10-16 新增）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `-OcrScale` | `1.25` | OCR 前放大倍数（`1` ＝关掉；**2 以上就是过头**） |
| `-NoOcrFix` | 关（＝修正开启） | 关掉 OCR 错字修正层（规则表在 `$script:OcrFixRules`） |
| `-NoRegion` | 关（＝分区开启） | 关闭分区 OCR，回到整张 OCR |
| `-RegionTitle` | `10,1330,0,88` | 标题列（同时是特殊版面预检的探针） |
| `-RegionMain` | `25,1330,100,776` | 主文字面板（故事全文） |
| `-RegionOpts` | `25,1330,783,1185` | 选项面板 |
| `-RegionChar` | `1155,1700,88,200` | 角色卡（整区不记事件） |
| `-RegionMinLines` | `5` | 分区总行数低于此 → 自动退回整张 OCR |
| `-ColorThreshold` | `24` | 楼层配色：色差多少才算“换楼层”（也是边界快取的失效门槛） |
| `-ColorSample` | `48` | 楼层配色：取样方块大小（像素） |
| `-AutoRegion` | **关** | 本帧直接用自动量到的新边界（只存记忆体，不改参数、不改文件） |

**窗口（10-16 新增）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `-WinSize` | `2091x1297` | 开录前强制浏览器窗口尺寸（含外框） |
| `-WinPos` | `right` | 窗口位置。`right` 贴齐右缘（保留尺寸）；`splitright` 是真正的右半贴靠（**会改尺寸，需重新校正**）；也能给 `x,y` |
| `-NoResize` | — | 完全不动窗口大小位置 |

**校正（10-16 新增）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Calibrate` | — | 只扫面板边界、印出建议坐标就结束（不录影） |
| `-CalibrateImage` | 无 | 搭配 `-Calibrate`：改读这个图档（必须是 render 区尺寸） |

**收尾**

| 参数 | 默认 | 说明 |
|---|---|---|
| `-WikiAll` / `-WikiSession` | — | 重建 wiki（全部／单一场次，不删东西） |
| `-Export` / `-ExportAll` | — | 导出最新补充然后清空 logs／完整重汇（忽略上次导出记录） |

## 疑难排解

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 看到 `刁吣！`（应该是“小心！”）、`理智．1`（应该是 `-1`） | Windows OCR 把符号读错 | 这些**已经由修正规则自动修好**；还有残留就是 **Windows OCR 本身的限制**（换字体、调放大倍数只能改善，无法保证 100%）。想看未修的原样：加 `-NoOcrFix`，或直接查 `ocr-raw.log` |
| 分区抓不到内容（`wiki.md` 突然变很少、`logger.log` 一直出现“分区 OCR 退回整张 OCR”） | 窗口尺寸／浏览器缩放变了，**坐标跑掉** | 跑 **`-Calibrate`**，看量到的边界跟参数差多少；差 >10px 就用它印出的“新参数”那一行 |
| 窗口跑到不想去的位置 | `-WinPos` 的贴靠模式 | 用 `-WinPos left`／`center`／`x,y` 换位置，或 `-NoResize` 完全不动 |
| 背包／结局时记到的字变少 | **正常**：那三种特殊版面走整张 OCR，而且 `title`／`opts`／`char` 不套用 | 看 `logger.log` 的“版面=…”那几行，或 `ocr-raw.log` 帧标头的 `版面=` |
| `floor-colors.log` 一直冒出新的一笔 | 画面重绘让底色抖动超过门槛 | 把 `-ColorThreshold` 调高一点（例如 32） |
| 楼层配色跟 Wiki 的配色表不一样 | 快取里是自动值、Wiki 表是人工实测值（实测优先） | 自动值只记进 `alt`，不会覆盖实测值；要人工裁决就跑 `sync-floor-colors.ps1 -WhatIf` 看“冲突”列 |
| 明明有玩，收工却说“还没有新内容” | 上次导出后真的没有新增事件 | `-Export -ExportAll` 会忽略记录完整重汇一次 |
| 某几帧完全没东西 | 可能是分页被切走（会留 `>` 注记）、或窗口最小化 | 查 `ocr-raw.log` 有没有那几帧的标头、`logger.log` 有没有 `>` 注记 |
| 想先确认“现在这台机器认得顺不顺” | — | **先跑 `-Once`**：只抓一张、印出分区／版面／配色结果，不建场次也不会影响你的窗口（`-Calibrate` 同样安全） |

## 已知限制（诚实说明）

- **只有画面上看得到的字才会被记到。** 游戏没有导出功能，这是物理限制；不过每 1~2 秒抓一张，
  文字通常停留好几秒，实务上几乎都抓得到。
- **OCR 偶尔还是会认错字**：手写／像素风字体，常常是图示被当成字
  （头像被读成 `女`、`Level 5`→`Leve15`）。
  常见的**固定误读**已由 10-16 的修正层自动处理，但**无法保证 100%**，
  剩下的是 Windows OCR 本身的限制。**要和原文对照就查 `ocr-raw.log`**
  （那里是未过滤全文，而且有 `[区块名]` 与 `版面=` 可以追），或临时勾“保留截图”再跑一次。
- **分区 OCR 依赖固定窗口尺寸**。用了 `-NoResize`、或自己改过窗口大小／浏览器缩放，
  坐标就会偏，要重跑 `-Calibrate`。不确定就加 `-AutoRegion` 让它自己跟著走
  （但只影响当下那一帧，不会帮你改参数）。
- **背包／结局／弹窗三种版面是走整张 OCR 的**，那些画面本来就以 UI 为主，
  所以杂讯有可能又跑回来一点；`[item]` 标记可以帮你事后挑出物品／属性行。
  （这三种版面**实测机会不多**，目前只用合成特征验证过，真的遇到时看 `logger.log` 的“版面=…”最准。）
- **2026-10-14 之前录的 6 个场次是从 `ocr-raw.log` 补转的**（当初有坐标的中间档已清掉），
  所以那几场的队伍频道讯息会被归成 `N` 旁白，段落合并也比较保守。**新录的场次不受影响。**
- **切到别的浏览器分页时会自动暂停**，并在文件里留一行 `>` 注记，所以哪里有断点看得很清楚。
- **Edge 最小化时不记**（Chromium 最小化截不到画面）；被其他窗口盖住没关系，照样抓。
- 隔很久又出现的同一句话会被再记一次（它真的又出现在画面上了）。
- **小窗口（EXE）没有新功能的开关**：要用新功能只能用命令列跑 `.ps1`。

## 文件说明

| 文件 | 用途 |
|---|---|
| **`BackroomLogger.exe`** | ⭐ 开关小窗口（17 KB，用 Windows 内建的 .NET Framework，不用安装东西）。**没有** 10-16 新功能的开关 |
| `backroom-logger.ps1` | 引擎（PowerShell 5.1 + Windows 内建 OCR，**不连网**）。**必须跟 exe 放同一个文件夹，不能删** |
| `floor-colors-cache.json` | “楼层 → 底色”快取 ＋ 量到的面板边界（自动累积；删了下次会重新学，不影响录影） |
| `logs\` | 所有输出（每场次一个 `backroom-*` 文件夹） |
| `logs\*\floor-colors.log` | 这一场量到的各楼层界面配色 |
| `backroom-summary-*.md` / `backroom-update-*.md` | 收工产物；**`update` 是 wiki 出处行号的唯一依据，别删** |
| `export-state.json` | 增量导出的水位线（隐藏档） |
| `backroom-logger.ps1.bak-before-*` | 每次改版前的备份（ocrscale／forcewin／region／colorcal／ocrfix），出事要回溯，**先别删** |
| `..\交接.md` | 项目现况（接手先读；设计理由、踩过的坑、待办） |
| `..\wiki\_drafts\截圖分區座標.md` | 分区坐标的校正基准与量测依据（改窗口大小／缩放后要重写） |
| `..\wiki\sync-floor-colors.ps1` | 把各场 `floor-colors.log` 并进 Wiki 的配色表（`-WhatIf` 可先预览） |
| `說明.md` | 这份说明 |

> 不然 PowerShell 5.1 会把中文读成乱码。
>
> 改脚本前的备份惯例：`Copy-Item backroom-logger.ps1 backroom-logger.ps1.bak-before-<改了什麼>`
