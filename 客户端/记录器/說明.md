# 狐霖的後室 RPG — 畫面文字記錄器（Wiki 版）

把遊戲裡出現過的每一段文字，自動認成**結構化的 wiki 素材**存下來 ——
樓層、場景、旁白、決定、選項、擲骰、狀態變化、道具、隊伍頻道全部分開標記，
**可以直接丟給 AI 整理成 wiki**。只留文字、截圖用完即刪，在背景跑不干擾你玩。

> **2026-10-16 這版加了一堆「認得更準」的機制**：OCR 前放大、分區 OCR、
> 樓層配色自動記錄、OCR 錯字自動修正、三種特殊版面自動判斷。
> **日常玩法完全沒變**：雙擊 `BackroomLogger.exe`、按開始，就這樣。
> 只有想調細節（或不想讓它動你的視窗）才需要看下面的〈命令列〉。

---

## 為什麼是「看畫面」

這個遊戲是 **Unity WebGL**：所有文字都畫在一張 `<canvas>` 上，DOM 和無障礙樹裡
**一個字都沒有**（實際查過，只有 10 個空的圖片節點）。所以只能看畫面：

```
背景截圖 → 只裁遊戲畫面 → Windows 內建 OCR（不連網）→ 分類 → 圖立刻刪掉 → 寫成 wiki
```

2026-10-16 之後，中間那步「OCR」變得講究多了（放大、分區、修正），
但**整條路一樣是「看畫面」**，沒有變成讀網頁原始碼那種做法。

---

## 用法

雙擊 **`BackroomLogger.exe`**，一顆按鈕：

| 控制 | 作用 |
|---|---|
| **▶ 開始記錄 / ■ 停止記錄** | 同一顆切換（停止是優雅的：會刪暫存圖、寫完最後一筆才結束） |
| **每 N 秒抓一張** | 想抓更細就調 1 秒 |
| **☐ 保留截圖** | 平常不用勾 |
| **開啟 wiki.md** | 打開這一場的成果 |
| **重建／合併 Wiki** | 把所有場次重新整理成 `wiki-all.md` + `INDEX.md`（不刪東西，可放心多按） |
| **收工：匯出最新補充，然後清空 logs** | ⭐ **只匯出「上次之後的新內容」**成一個 `.md` 放在 exe 旁邊，然後清空 logs —— 另一個 agent 每次只讀新增的部分 |
| 狀態列 | 即時顯示跑了多久、已收幾個事件 |

### ⚠ 小視窗只會用「預設值」跑

`BackroomLogger.exe` 是 **2026-10-14 編的**，它只會傳 `-Interval`、`-SaveFrames`、
`-StopFile`、`-WikiAll`、`-Export` 這幾個舊參數。**10-16 的新功能它一顆開關都沒有**，
所以雙擊 EXE ＝ 用預設值跑，其中兩個預設值會直接影響你：

| 預設行為 | 你會看到的 |
|---|---|
| **開錄前把遊戲視窗改成 `2091x1297`（位置不動）** | 視窗尺寸被改掉；**位置不會被搬動** |
| OCR 放大 1.25 倍、分區 OCR、OCR 錯字修正：**三個都預設開** | 認得更準，但你會發現 wiki 的字變乾淨了 |

**不想被搬視窗**（例如正在用大螢幕、或想邊玩邊做別的事）：

```powershell
.\backroom-logger.ps1 -WinPos ''      # 只改尺寸，位置不動
.\backroom-logger.ps1 -NoResize       # 尺寸位置都不動
```

改視窗大小是**不搶焦點**的（用 `SetWindowPos` ＋ `SWP_NOACTIVATE|SWP_NOZORDER`），
不會把你從別的視窗踢走；改完還會**等 2.5 秒**讓 Unity 重新排版再開始抓。

## OCR 怎麼認得更準（2026-10-16 新增）

### 1. 先放大再認：`-OcrScale`（預設 `1.25`）

Windows OCR 對這種小字＋像素風字體很吃力，常見的錯法是**把一個中文字拆成部首**。
把圖放大再送 OCR 就修好了，但**放大過頭反而更糟**：

| 倍數 | 結果 |
|---|---|
| `1`（＝關掉） | 原樣，`你`容易被讀成`亻尔`、`前任`→`甫亻壬` |
| **`1.25`（預設，實測最佳）** | 部首拆解修好（`亻尔`→`你`、`甫亻壬`→`前任`），**又不會**把 `Level` 讀成 `LeveI` |
| `2` 以上 | **過頭**：連 `Level` 都被讀成 `LeveI`，整體變差 |

放大是用高品質雙三次內插（`HighQualityBicubic`），而且**裁切一定在放大之前**
（座標是原圖的，放大後才不會對不上）。

### 2. 分區 OCR：一次只看四個區塊（預設開，`-NoRegion` 關掉）

**為什麼要分區**：整窗 OCR 會把畫面上所有字一起吃進來，包括右上角的按鈕列
（`催促`、`背包 (B)`、`离开`）和右側的隊伍頻道聊天（`跟我走！`、`哈哈`），
這些**介面與聊天文字會混進 wiki 正文**，事後要靠關鍵字一條一條濾，很容易漏。

分區之後，OCR 只看這四塊（實測**雜訊歸零**：`催促／背包 (B)／离开／跟我走！／哈哈／送出`
等 10 個詞在分區模式下**出現 0 次**）：

| 區塊 | 預設座標 `x0,x1,y0,y1` | 內容 |
|---|---|---|
| `title` | `10,1330,0,88` | `Level N「名稱」` ＋ `第 N 層 \| 難度 \| 區域` |
| `main` | `25,1330,100,776` | **主文字面板：故事全文（OCR 主力）** |
| `opts` | `25,1330,783,1185` | `要走哪條路？`／`要怎麼做？` ＋ 選項 |
| `char` | `1155,1700,88,200` | 角色卡（名字／Lv／職業／HP／MP）—— **整區都是介面，不記事件** |

- 座標是 **render 區（實際送 OCR 的那張圖）的像素**，校正基準 `2067x1205`；
  實際 render 區尺寸不一樣時會**自動等比縮放**。
- **`-RegionMinLines`（預設 `5`）**：分區加起來不到 5 行、或某一區 OCR 失敗
  → **自動退回整張 OCR**，並在 `logger.log` 記一筆警告（那一幀的行首標記會變成 `[full]`）。
  所以「畫面怪怪的」不會直接變成一堆空資料。
- **`-NoRegion`**：整層關掉，回到以前的整張 OCR。
- **`-AutoRegion`（預設關）**：開啟時，本幀若量到跟參數差超過 10px 的新邊界，
  **這一幀就直接用新邊界**——只存在記憶體，**不改參數、不改任何檔案**。

### 3. `ocr-raw.log` 多了「區塊標記」

以前 `ocr-raw.log` 只有一行行文字，現在每一行前面會標**它是從哪一區來的**，
每一幀的標頭也會寫**配色**與**版面**：

```
[2026-10-16 07:04:32] 原始 OCR 逐幀記錄（完整保留，未經過濾）
===== 2026-10-16 07:04:35 幀 #1 2067x1205 (OCR 2067x1205) 配色=#2E2813 版面=normal 行數=21 =====
[title] Level 0 「大厅」
[title] 等大家决定一
[main] 回过神来，你已经摔在一片湿湿的地毯上。……
```

| 標記 | 意思 |
|---|---|
| `[title]` / `[main]` / `[opts]` / `[char]` | 分區 OCR 的來源區塊 |
| `[full]` | 這一幀走**整張 OCR**（特殊版面，或分區退回） |
| `[item]` | 背包面板裡的物品／屬性行（方便事後挑出來） |
| 幀標頭 `配色=#RRGGBB` | 這一幀在 `main` 區取樣到的面板底色 |
| 幀標頭 `版面=normal\|backpack\|ending\|panel` | 這一幀被判斷成哪種版面 |

懷疑 OCR 認錯字、或想知道「這行是哪來的」，**就是回來查這個檔**。

### 4. 樓層配色自動記錄

每一幀都在 `main` 區右上角**沒有文字的一小塊**取樣平均色（大小＝`-ColorSample`，
預設 `48` 像素方塊，往內縮 40px 避開文字）。底色變化超過 **`-ColorThreshold`（預設 `24`）**
就寫一筆到 `floor-colors.log`（樓層名從 `title` 區 OCR 抓）：

```
[2026-10-16 07:04:32] 各樓層介面配色（自動偵測；底色變化超過 24 就記一筆）
2026-10-16 07:04:35  #2E2813  rgb(46,40,19)  Level 0 「大厅」  幀#1
```

同一份配色也會**累積**到 exe 旁邊的 **`floor-colors-cache.json`**：

- 種子＝ `backroom-wiki\_data\_floor-colors.md` 的**人工實測配色表**（那張表最高權威，
  **實測值永不被自動值覆蓋**）。
- 之後由每一場的 `floor-colors.log` 自動累積（樓層 → 底色、出現次數、來源）。
- 同一層出現不同色（換區域、彈窗底色）→ 主色不動，新的色碼記進 `alt` 讓人看。
- 這個快取同時是「自動校正分區」的依據：每幀先用底色比對「最接近哪一層」，
  拿該層的預期底色當掃描種子色。**沒快取、或色差超過門檻**才會做全圖掃描
  （同一層一次、至少間隔 4 秒），所以不會拖慢每一幀。

配色也會**寫進輸出**（只新增欄位，不動既有格式）：
`wiki.md` 的樓層段落後面多一行 `<!-- color:#RRGGBB -->`，
`wiki.jsonl` 的樓層事件多一個 `color` 欄位。

**同步回 Wiki**：`D:\BACKROOMS\wiki\sync-floor-colors.ps1`
會把各場 `floor-colors.log` 併進 `_data\_floor-colors.md` 的配色表
（先加 `-WhatIf` 看它打算加什麼）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sync-floor-colors.ps1 -WhatIf
powershell -NoProfile -ExecutionPolicy Bypass -File .\sync-floor-colors.ps1
```

它**只讀** log、**只寫**那張表；新樓層新增一列，同層不同色**不覆蓋原列**，
而是另外加一列標成「衝突」等人裁決，重複執行也安全。

### 5. OCR 錯字修正（預設開，`-NoOcrFix` 關掉）

Windows OCR 對這個遊戲有**固定且會重複發生**的誤讀。與其每次事後人工比對，
現在在「正規化（清空白）」之後多套一層規則表，把**確定不會誤傷**的誤讀修回來。

- 規則表在 `backroom-logger.ps1` 上方的 **`$script:OcrFixRules`**（共 11 條）。
- **資料驅動**：每條寫成 `@(類型, 樣式, 取代值, 說明)`
  - `'x'` ＝固定字串取代
  - `'r'` ＝規則運算式（全部取代）
  - `'r1'`＝規則運算式，只換第一筆
  - 執行順序＝陣列順序（上面的先跑），所以**有相依的規則順序不能顛倒**
- **要調就直接改那張表**（停用某條：在它前面加 `#` 或整條刪掉）。
  每條旁邊都有註解寫「為什麼這樣改是安全的」。
- **`-NoOcrFix`** 可以整層關掉（正規化、分類都不受影響）。

已經處理的誤讀（節錄）：

| 誤讀 | 修正 | 為什麼安全 |
|---|---|---|
| `刁吣！`／`刂吣！`／`刁 № 心！` | `小心！` | 只認**整行**就是這幾個字形組合（快速聊天鈕），正文不會整行只有這些 |
| `亻尔` / `甫亻壬` | `你` / `前任` | 部首被拆開的組合，正常中文不會出現（`甫亻壬` 那條要排在 `亻尔` 前面） |
| `LeveI` / `Leve1` / `Leve15` | `Level` / `Level5` | 兩條規則、順序不能反：先處理「`leve1` 後面接數字」，再處理剩下的 |
| `理智．1`（`體力·2` 這類） | `理智 -1` | 只在「**已知狀態名** ＋ 分隔符 ＋ 一位數字（後面不是數字）」時換 |
| `〔…〕`／`〖…〗` | `【…】` | 只換「整行就是一組外框」的場景標題 |
| `第 2 层《岔路` | `第 2 层 \| 岔路` | 只作用在「第 N 层」開頭的標題行 |
| `徒出了这」层` | `走出了这一层` | 只認這個固定短語，且**沒有錨定行尾**（OCR 常把它跟後半句黏成一行） |
| 數字中間的 `．`／`·` | `.` | 只在「數字．數字」時換，句尾的 `。` 不受影響 |

**這是保守設計**：實測 22 條樣本裡，13 條真的誤讀被修正、**9 條正常文字完全沒被動到**。
`-NoOcrFix` 之下 22 條原樣不變、一個字都沒改。

### 6. 三種特殊版面：背包／結局／彈窗

分區座標**只對「標準遊玩畫面」有效**。這三種版面會整個蓋掉標準版面，
硬套分區會把大段文字切掉，所以：

| 版面 | 怎麼認 | 結果 |
|---|---|---|
| `backpack`（背包與裝備） | 出現「背包与装备／裝備欄」之類字樣 | 改用整張 OCR，物品／屬性行**另外標 `[item]`** |
| `ending`（全螢幕結局） | **整片近黑**（中央大半取樣區 90% 以上亮度 < 40），或出現「跳过」 | 改用整張 OCR |
| `panel`（彈窗三欄面板） | 出現「编号／雕刻／门后」，或「任務＋目標」這種欄位名 | 改用整張 OCR |

做法是**兩段偵測**：

1. **便宜預檢**：只 OCR 標題列那一小條（約 1300x88）。標準畫面的標題列一定有
   `Level N「…」`，**看不到就代表不是標準畫面** → 改用整張 OCR。
   （只多花一次小區塊 OCR，不是每幀都整張 OCR 兩次。）
2. 整張 OCR 之後再依**文字特徵**分背包／三欄面板、依**顏色**分結局。

特殊版面時 **`title`／`opts`／`char` 三個分區不套用**（才不會把大段文字切掉），
那一幀的行首標記是 `[full]`，幀標頭寫 `版面=…`，`logger.log` 也會記一筆版面變化。

### 7. 視窗尺寸鎖定：`-WinSize` / `-WinPos` / `-NoResize`

分區座標是**固定像素**，所以**視窗尺寸是分區裁切的前提**——
視窗一變大變小，座標就跑掉了。因此開錄前會先：

```
-WinSize 2091x1297  -WinPos （空）    →   SetWindowPos（不搶焦點、不改 Z 序）
```

- `-WinSize`：`寬x高`（**含瀏覽器外框**），預設 `2091x1297`。
- `-WinPos`：**預設 `right` ＝ 貼齊螢幕右緣（保留尺寸）**。其他關鍵字：`topright`／`left`／`center`／`splitright`／`splitleft`（後兩者是 Windows 真正的半螢幕貼靠，**會改變尺寸 → 需要重新 `-Calibrate`**）；也可直接給 `x,y`；留空 = 完全不動位置。
- `-NoResize`：**完全不動**視窗（適合你已經自己排好版面、或不想被搬）。
- 螢幕放不下時會被系統夾住，工具列會印出「實際 WxH，要求 WxH」提醒你。

## 換了環境就要重新校正：`-Calibrate`

**什麼時候要重跑**（任何一個變了就要）：

- 換**樓層配色**（不同樓層面板底色不一樣）
- 換**瀏覽器縮放**（不是 100% 時比例會變）
- 換 **`-WinSize`**（或改過視窗大小）
- 換**螢幕／解析度**

跑法（**不錄影、不會動你的視窗**）：

```powershell
# 直接看現在的遊戲視窗
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Calibrate

# 或 用一張現成的圖檔（圖必須是 render 區尺寸）
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -CalibrateImage 'C:\Users\HX\Desktop\后室RPG-参考截图\_即時frame_2067x1205.jpg'
```

它會印出：

1. **量到的面板**：`main`／`opts` 的底色、取樣點、上下界與左右界、空白分隔帶
2. **用目前參數試跑一次分區 OCR**：每一區抓到幾行、前 10 行長什麼樣
   （**這步最重要**：看得到內容才代表座標對）
3. **樓層配色快取比對**：偵測到哪一層、取樣色 vs 快取預期色、是否一致
4. **與目前參數比較**：差 **>10px** 就標 ⚠（只警告「量到比預設窄」，因為量到更寬
   可能只是把同色的隔壁面板算進來）
5. **可直接複製的新參數**：一行 `-RegionTitle '…' -RegionMain '…' -RegionOpts '…' -RegionChar '…'`

校正完也會把量到的邊界寫進 `floor-colors-cache.json`（錄影時就直接用得到）。

> **座標的依據存在 `D:\BACKROOMS\wiki\_drafts\截圖分區座標.md`**
> —— 裡面有校正基準（螢幕 / 視窗外框 / render 區尺寸）、每個區塊的座標與說明、
> 以及量測依據（逐欄逐列的底色命中率）與量測腳本。
> **改動視窗大小或瀏覽器縮放時，那份要重寫。**

## 輸出格式（給 AI 用的）

每場次一個資料夾 `logs\backroom-YYYYMMDD-HHMMSS\`：

| 檔案 | 內容 |
|---|---|
| **`wiki.md`** | ⭐ 主要成果：結構化逐字稿，AI 可以直接拿去寫 wiki |
| `wiki.jsonl` | 同一份資料的事件流（一行一事件，有型別），要精確處理時用 |
| `ocr-raw.log` | **未過濾**的原始 OCR 全文（每幀都留）。每行前面有 `[區塊名]`、幀標頭有 `配色=`／`版面=` —— 懷疑 OCR 認錯字、或想知道某行怎麼來的就查這裡 |
| `floor-colors.log` | 這一場量到的**各樓層介面配色**（底色變化超過門檻就記一筆） |
| `logger.log` | 程式自己的運行記錄（含分區退回、版面變化、自動校正掃描、建議座標） |
| `frames\` | 只有加 `-SaveFrames` 才會有；預設不留截圖 |

`wiki.md` 長這樣：

```markdown
## Level 0 「大厅」
<!-- color:#302810 -->

### 〖开场的铃声〕
@ 08:10:37
N 单调的黄色壁纸、潮湿的地毯、到处都是的电源插座，还有头顶那永远不会停的日光灯嗡嗡声。
D 你决定：「往传来「叮——」的一声的方向走」
O 跟着铃声的节奏，带你往前走（魅力 難度11）｜捂住耳朵，快走
Q 天狐：跟我走！
C 魅力 難度11 天狐 · 魅力检定 · 难度 11
R 魅力 難度11 天狐 5+5=10 失敗
S 天狐：理智 -2、口渴 +1
I 天狐：得到「急救毯」
```

### 標記對照

| 標記 | 意思 | 為什麼對 AI 有用 |
|---|---|---|
| `##` / `###` | 樓層 / 場景 | 直接就是 wiki 的頁面與段落標題 |
| `<!-- color:#RRGGBB -->` | 這層的介面配色 | 對照 Wiki 的配色表（10-16 新增） |
| `@ 時:分:秒` | 時間 | 只在跨分鐘或間隔 >15 秒時標，省 token 又保留時間軸 |
| `N` | 旁白 | wiki 的正文 |
| `D` | 決定 | 玩家做了什麼選擇 |
| `O` | 選項（含檢定難度） | 選項樹、每個選項要骰什麼 |
| `R` | 擲骰結果 | `技能 難度 誰 骰值=總值 成功/失敗`（欄位化） |
| `C` | 檢定宣告 | 即將進行的檢定 |
| `S` | 狀態變化 | 體力/理智/口渴/經驗/出口進度 |
| `I` | 道具 | 得到、撿起 |
| `Q` | 隊伍頻道 | 隊友對話 |
| `>` | 記錄中斷 | 什麼時候切走了分頁、暫停多久 |

### 為了「省」做的事

- **同一段旁白合併成一行**（OCR 常把一段話切成兩三行）
- **介面雜訊不記**：按鈕、提示文字、快捷聊天鈕、`已決定`、`思考中` 之類全部濾掉 ——
  現在有**兩層防線**：先靠**分區 OCR** 從源頭不看那些區塊，再靠關鍵字清單補刀
- **角色卡不記事件**：`char` 區整區都是介面（名字／Lv／職業／HP／MP），整區不進 wiki
- **同一句話不重複收**（含模糊比對；遊戲重繪畫面時不會灌爆）
- **半截片段不收**：已經有更完整的同一句時，短的殘缺版會被丟掉
- **時間只在需要時標**，其他全靠順序
- **截圖不留**：OCR 完立刻刪，跑好幾小時也只有幾百 KB

## 兩種收尾方式

### 1. 重建／合併 Wiki（不刪東西）

按「重建／合併 Wiki」或命令列 `-WikiAll`：

| 檔案 | 內容 |
|---|---|
| `logs\wiki-all.md` | 所有場次按時間合併成**一份**，AI 整理 wiki 的單一入口 |
| `logs\INDEX.md` | 場次索引：每場的開始時間、事件數、走過的樓層 |

各場次的 `wiki.md` 也會順便重新整理。同一個事件流重跑幾次結果都一樣（冪等），可以放心多按。

### 2. 收工：匯出「最新補充」，然後清空（⭐ 要拖給 AI 用這個）

按 **「收工」**（或命令列 `-Export`）會先停掉記錄器，然後在 **exe 旁邊產生兩個檔案**，
最後刪掉 `logs` 底下所有場次資料夾：

| 檔案 | 大小 | 用途 |
|---|---|---|
| **`backroom-summary-*.md`** | 小（實測 2.45 MB 的紀錄 → **88 KB**，其中 ① 摘要只有 350 行 / 1.3 萬字元） | ⭐ **拖這個給 AI** |
| `backroom-update-*.md` | 大（約原始的 60%，已去重去雜訊但不截斷） | 留著當 **wiki 出處**的依據 |

### 為什麼讀起來快很多

匯出時會做四件事（實測在同一份 2.45 MB 紀錄上）：

| 處理 | 效果 |
|---|---|
| 全域去重（不只比最近 240 行） | 去掉 **45%** 完全重複的行 |
| 去掉 OCR 碎裂雜訊（符號比中文多的行、太短的碎片） | 再去掉一大批 `墨 / 」、｜司吊月豕只…` 這種垃圾 |
| 樓層／場景標題只在「變了」的時候留一次 | 去掉 3,000 多個重複標題 |
| `C` 檢定宣告 + 緊接的 `R` 擲骰結果 → 合併 | 少一半重複資訊 |

`backroom-summary-*.md` 的結構：

```
① 快速摘要（約 350 行，先讀這段通常就夠）
   走過的樓層 / 場景（含所屬樓層）/ 這次拿到的道具
   檢定擲骰彙總（各技能難度的成功失敗次數、骰值例）
   出現過的選項（去重）/ 機制關鍵句（含技能、傷害、狀態、效果…）
   每個場景代表句（最長的一句，快速抓到發生什麼）
② 重點事件（結構化事件全留、旁白只留 ≥20 字的、不含隊伍頻道、各段有筆數上限）
   —— 被上限省略的筆數會列出來，完整內容指向完整檔
```

**閱讀量：** 原始 99 萬字元 → ① 摘要 1.3 萬字元 = **約 78 倍快**。

**關鍵：不會每次重寫全部歷史。** 匯出到哪會記在 `export-state.json`（隱藏檔），
下次只拿新的部分 —— 另一個 agent 每次只要讀那一小份補充。

- 同一場玩到一半按「收工」，下次也只會拿到那場之後新增的事件（不會重複）
- 上次之後沒有新東西 → 不會產生檔案，直接告訴你「還沒有新內容」
- 想忽略記錄、**完整**重匯一次：`-Export -ExportAll`
- 完整檔（`backroom-update-*.md`）是 wiki 出處的唯一依據，**別刪**；建議複製到 `backroom-wiki\來源紀錄\`

> 想留底：刪掉之前把 `logs` 整個資料夾複製一份就好。
> 場次還在錄影中不會被匯出（會提示你先停止），所以不會刪到正在寫的檔案。
> ⚠ 收工會清掉 `logs`，所以**收工前先跑一次 `sync-floor-colors.ps1`**，
> 免得這幾場量到的樓層配色還沒併進 Wiki 就被清掉了。

## 命令列（一般用不到）

```powershell
# 平常（照預設值：視窗固定成 2091x1297 並貼齊螢幕右緣，分區＋放大＋錯字修正都開）
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1

# 只抓一張測試（最安全，不錄影、不建場次）
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Once

# 不想被搬視窗
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -WinPos ''
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -NoResize

# 每秒一張 / 重建合併 / 收工
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Interval 1
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -WikiAll
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Export

# 換了縮放或樓層配色，重新校正分區座標
powershell -ExecutionPolicy Bypass -File .\backroom-logger.ps1 -Calibrate
```

### 參數一覽（實際預設值以這份為準）

**基本**

| 參數 | 預設 | 說明 |
|---|---|---|
| `-Interval` | `2.0` | 每隔幾秒抓一張 |
| `-OutDir` | `.\logs` | 輸出資料夾 |
| `-Language` | `zh-Hans-CN` | OCR 語言（另有 `en-US`） |
| `-Hwnd` | `0`（自動找） | 直接指定視窗代碼 |
| `-TitleMatch` | `後室\|Backrooms\|狐霖\|hulin` | 用視窗標題找遊戲 |
| `-Once` | — | 只抓一張、印出結果就結束（測試用） |
| `-Quiet` | 關 | 不要在主控台印每一行 |
| `-SaveFrames` | 關 | 保留截圖當證據（預設刪） |
| `-KeepFrames` | `200` | 只有 `-SaveFrames` 時有用 |
| `-StopFile` | 無 | 出現這個檔案就收工（EXE 的停止鈕用） |

**認得更準（10-16 新增）**

| 參數 | 預設 | 說明 |
|---|---|---|
| `-OcrScale` | `1.25` | OCR 前放大倍數（`1` ＝關掉；**2 以上就是過頭**） |
| `-NoOcrFix` | 關（＝修正開啟） | 關掉 OCR 錯字修正層（規則表在 `$script:OcrFixRules`） |
| `-NoRegion` | 關（＝分區開啟） | 關閉分區 OCR，回到整張 OCR |
| `-RegionTitle` | `10,1330,0,88` | 標題列（同時是特殊版面預檢的探針） |
| `-RegionMain` | `25,1330,100,776` | 主文字面板（故事全文） |
| `-RegionOpts` | `25,1330,783,1185` | 選項面板 |
| `-RegionChar` | `1155,1700,88,200` | 角色卡（整區不記事件） |
| `-RegionMinLines` | `5` | 分區總行數低於此 → 自動退回整張 OCR |
| `-ColorThreshold` | `24` | 樓層配色：色差多少才算「換樓層」（也是邊界快取的失效門檻） |
| `-ColorSample` | `48` | 樓層配色：取樣方塊大小（像素） |
| `-AutoRegion` | **關** | 本幀直接用自動量到的新邊界（只存記憶體，不改參數、不改檔案） |

**視窗（10-16 新增）**

| 參數 | 預設 | 說明 |
|---|---|---|
| `-WinSize` | `2091x1297` | 開錄前強制瀏覽器視窗尺寸（含外框） |
| `-WinPos` | `right` | 視窗位置。`right` 貼齊右緣（保留尺寸）；`splitright` 是真正的右半貼靠（**會改尺寸，需重新校正**）；也能給 `x,y` |
| `-NoResize` | — | 完全不動視窗大小位置 |

**校正（10-16 新增）**

| 參數 | 預設 | 說明 |
|---|---|---|
| `-Calibrate` | — | 只掃面板邊界、印出建議座標就結束（不錄影） |
| `-CalibrateImage` | 無 | 搭配 `-Calibrate`：改讀這個圖檔（必須是 render 區尺寸） |

**收尾**

| 參數 | 預設 | 說明 |
|---|---|---|
| `-WikiAll` / `-WikiSession` | — | 重建 wiki（全部／單一場次，不刪東西） |

## 疑難排解

| 症狀 | 原因 | 怎麼辦 |
|---|---|---|
| 看到 `刁吣！`（應該是「小心！」）、`理智．1`（應該是 `-1`） | Windows OCR 把符號讀錯 | 這些**已經由修正規則自動修好**；還有殘留就是 **Windows OCR 本身的限制**（換字型、調放大倍數只能改善，無法保證 100%）。想看未修的原樣：加 `-NoOcrFix`，或直接查 `ocr-raw.log` |
| 分區抓不到內容（`wiki.md` 突然變很少、`logger.log` 一直出現「分區 OCR 退回整張 OCR」） | 視窗尺寸／瀏覽器縮放變了，**座標跑掉** | 跑 **`-Calibrate`**，看量到的邊界跟參數差多少；差 >10px 就用它印出的「新參數」那一行 |
| 視窗跑到不想去的位置 | `-WinPos` 的貼靠模式 | 用 `-WinPos left`／`center`／`x,y` 換位置，或 `-NoResize` 完全不動 |
| 背包／結局時記到的字變少 | **正常**：那三種特殊版面走整張 OCR，而且 `title`／`opts`／`char` 不套用 | 看 `logger.log` 的「版面=…」那幾行，或 `ocr-raw.log` 幀標頭的 `版面=` |
| `floor-colors.log` 一直冒出新的一筆 | 畫面重繪讓底色抖動超過門檻 | 把 `-ColorThreshold` 調高一點（例如 32） |
| 樓層配色跟 Wiki 的配色表不一樣 | 快取裡是自動值、Wiki 表是人工實測值（實測優先） | 自動值只記進 `alt`，不會覆蓋實測值；要人工裁決就跑 `sync-floor-colors.ps1 -WhatIf` 看「衝突」列 |
| 明明有玩，收工卻說「還沒有新內容」 | 上次匯出後真的沒有新增事件 | `-Export -ExportAll` 會忽略記錄完整重匯一次 |
| 某幾幀完全沒東西 | 可能是分頁被切走（會留 `>` 註記）、或視窗最小化 | 查 `ocr-raw.log` 有沒有那幾幀的標頭、`logger.log` 有沒有 `>` 註記 |
| 想先確認「現在這台機器認得順不順」 | — | **先跑 `-Once`**：只抓一張、印出分區／版面／配色結果，不建場次也不會影響你的視窗（`-Calibrate` 同樣安全） |

## 已知限制（誠實說明）

- **只有畫面上看得到的字才會被記到。** 遊戲沒有匯出功能，這是物理限制；不過每 1~2 秒抓一張，
  文字通常停留好幾秒，實務上幾乎都抓得到。
- **OCR 偶爾還是會認錯字**：手寫／像素風字體，常常是圖示被當成字
  （頭像被讀成 `女`、`Level 5`→`Leve15`）。
  常見的**固定誤讀**已由 10-16 的修正層自動處理，但**無法保證 100%**，
  剩下的是 Windows OCR 本身的限制。**要和原文對照就查 `ocr-raw.log`**
  （那裡是未過濾全文，而且有 `[區塊名]` 與 `版面=` 可以追），或臨時勾「保留截圖」再跑一次。
- **分區 OCR 依賴固定視窗尺寸**。用了 `-NoResize`、或自己改過視窗大小／瀏覽器縮放，
  座標就會偏，要重跑 `-Calibrate`。不確定就加 `-AutoRegion` 讓它自己跟著走
  （但只影響當下那一幀，不會幫你改參數）。
- **背包／結局／彈窗三種版面是走整張 OCR 的**，那些畫面本來就以 UI 為主，
  所以雜訊有可能又跑回來一點；`[item]` 標記可以幫你事後挑出物品／屬性行。
  （這三種版面**實測機會不多**，目前只用合成特徵驗證過，真的遇到時看 `logger.log` 的「版面=…」最準。）
- **2026-10-14 之前錄的 6 個場次是從 `ocr-raw.log` 補轉的**（當初有座標的中間檔已清掉），
  所以那幾場的隊伍頻道訊息會被歸成 `N` 旁白，段落合併也比較保守。**新錄的場次不受影響。**
- **切到別的瀏覽器分頁時會自動暫停**，並在檔案裡留一行 `>` 註記，所以哪裡有斷點看得很清楚。
- **Edge 最小化時不記**（Chromium 最小化截不到畫面）；被其他視窗蓋住沒關係，照樣抓。
- 隔很久又出現的同一句話會被再記一次（它真的又出現在畫面上了）。
- **小視窗（EXE）沒有新功能的開關**：要用新功能只能用命令列跑 `.ps1`。
