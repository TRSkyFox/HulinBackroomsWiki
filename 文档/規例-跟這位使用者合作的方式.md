# 規例 — 跟這位使用者合作的方式

> **給任何 agent 的第一份必讀文件。**
> 這不是技術文件，是**行為規則**。每一條都是實際被糾正過的，不要打折。
> 搭配 `交接.md`（專案現況）一起讀；技術細節與踩坑記錄看 `AGENTS.md`。
> （使用者口語說的「規例.md」就是這個檔。）

---

## 第 0 條：最重要的一條

> **使用者說「設計示例」就是設計示例，說「真實站」就是真實站。**
> **改錯檔案是最嚴重的錯誤。**

**發生過**：使用者要求「在 wiki 設計示例裡」改事件瀏覽器，我派 agent 去改了真實站的 `build-site.ps1`（900 行）。
使用者回：「**我让你做在wiki设计示例里 你做哪里去了**」。

### 規則

```
✅ 每次動手前，先確認要改的是哪個檔案，並在回覆裡【明講】
✅ 不確定就問一句「改 `_drafts\設計示例-我自己做.html` 還是 `build-site.ps1`？」
✅ 改完要證明【其他檔案沒動】（貼 mtime 或雜湊）
❌ 不要「順手」把改動套到別的檔案
❌ 不要「反正遲早要用」就自作主張
```

---

## 第 1 條：先約定外形，再動手

> **使用者原話：「先等等 我们先约定事件浏览器的外形」**

```
✅ 大改動之前，先問清楚或先提方案（外形／佈局／互動）
✅ 提出方案時用 ASCII 圖或清楚的文字描述，讓他能一眼看懂
✅ 他同意後才動手
❌ 不要自己先做一大堆，做完才讓他看（他會說「跑偏了」）
```

**⚠️ 但也不要問太多**：一次問 **1~3 個關鍵問題**，不要列十個選項讓他選。
（他有時會不耐煩：「**请快点**」）

---

## 第 2 條：截圖上的箭頭／圈／顏色，多半只是**標註**

> **使用者原話：「不要用颜色啊啊啊 我只是用了这个颜色的箭头告诉你哪个是哪个 不是让你用那个颜色！！」**

```
❌ 他在截圖上畫的【箭頭顏色、圈選顏色】通常只是【指出位置】，不是要你用的配色
✅ 要看的是「箭頭指向哪裡」，不是「箭頭是什麼顏色」
⚠️ 真的要用他的顏色時，他會明講（例如「用 #FFC23D」）
```

**同理**：他圈的範圍通常是「**這幾個東西要改**」，不是「這個範圍要保留」。

---

## 第 3 條：改完一定要**實際渲染**驗證，不是只看語法

> **發生過**：`node --check` 過了（語法 OK），但 HTML 元素沒插入，
> `getElementById(...).addEventListener` 拋 `TypeError` → **整支 script 死掉**
> → 頁面空白／路徑列表空／按鈕不見。使用者回：「**跑偏了**」。

```
✅ 語法檢查（node --check / PowerShell AST）
✅ ⭐ 用無頭瀏覽器【實際載入】→ 確認 JS 例外 = 0（不是只有語法 OK）
✅ ⭐ 【截圖】自己先看一眼，確認畫面是對的（不是只貼數據）
✅ 確認關鍵元素真的存在（querySelector 有結果、數量對）
❌ 不要只貼「node --check exit 0」就說做完了
```

**⚠️ 而且【自己先看截圖】** —— 很多時候問題一眼就看得出來
（按鈕掉到第二行、清單是空的、標題列擠爆）。

---

## 第 4 條：不要編造，缺就寫「（尚無資料）」

```
✅ 缺資料 → 寫「（尚無資料）」，並在回覆裡說「這幾項沒資料」
✅ 不確定 → 標「（推定）」或「⚠ 待確認」
❌ 不要用「大概」「應該是」填空
❌ ❌ 特別是【機率】和【數值】—— 沒有證據就不要寫數字
```

**⚠️ 樣本過少不寫機率**（既有規則）；有樣本就帶樣本數，例如「約 1/3（樣本 3 次）」。

---

## 第 5 條：玩家名 ≠ 角色名（**這條錯了會被罵**）

```
❌ 玩家名一律移除 → 換成「<玩家>」或「你」
   例：加菲／狐天／白落／小楓／小獵／小狙／Wiki探索者
       狐跑跑／槍客貓／noodlesfox／夭狐／禾狐／檔案員／探索者

✅ 角色名要保留
   諾亞／湯瑪斯／光明／狐霖／霧狐／遊魂／面狐／鹿其／陽／陰／米香／灰狼／
   星龍／呐豆／小猦／御影／庫特斯／奈茲米／靈音／菟耳絲／鬼月／小羅／小櫻／
   鳳凰／神話／小霏／喵汰／銀夕／雷夫／天雀／白桃／Tmatpd／紅豆／十龍／懶狼

⚠️【天狐】與【O₂】已經是遊戲內角色（2026-10-18 更新）→ 不要當玩家名刪掉
⚠️ 判斷方式：① 看角色面板 ② 去 `頁面\09-角色名錄.md` 查證
⚠️ 查不到 ≠ 不是角色 —— 可能是別名或名錄還沒收
⚠️ 不確定就【問使用者】，不要自己判定成玩家名刪掉
```

**面板判斷法**：上方大字＝玩家帳號名；下方小字＝`角色名｜稱號`。
例：`天狐`（上）＋ `小猦｜畫布中的執筆者`（下）→ 玩家「天狐」在玩角色「小猦」，
Wiki 寫「小猦」或「你」；**不是**把「天狐」當文本、也**不是**把「小猦」刪掉。

**字形陷阱**：`呐`/`納`、`猦`/`獵`、`楓`/`枫`（繁簡異體，比對時要同時試）

**⚠️ 同名陷阱**：「懶狼」**既是玩家帳號名、也是一隻角色名**（稱號「向陽的細劍」）。
判斷法：**屬性總和 13 ＝ 固定角色；12 ＝ 自訂角色**。

---

## 第 6 條：對話用**簡體**，內容用**繁體**

> **使用者原話：「我其实在江苏无锡 只是游戏默认繁体中文 请用简体和我说话」**

```
✅ 跟使用者對話（回覆、說明、提問、進度報告）→ 【簡體中文】
✅ Wiki 頁面內容、專案文件、腳本註解 → 【繁體中文】
✅ 遊戲內文字 → 照抄（遊戲預設繁體）
⚠️ 不要因為遊戲是繁體，就假設他習慣繁體
```

---

## 第 7 條：程式紅線（**違反會出人命**）

### 7.1 絕對不要用程序名稱批次關程式

```powershell
# ❌❌❌ 全部禁止
Stop-Process -Name msedge
taskkill /IM chrome.exe
Get-Process xxx | Stop-Process
Get-Process node | Where-Object { $_.CommandLine -like '*adobe*' } | Stop-Process

# ✅ 只關自己啟動、明確記下 PID 的
$p = Start-Process ... -PassThru
Stop-Process -Id $p.Id
```

**實際事故**：
```
2026-10-14：殺掉使用者正在玩的 Edge 遊戲
2026-10-17：用 -like '*路徑關鍵字*' 誤殺 Adobe 的 node
```

### 7.2 使用者的 Edge 絕對不要碰

```
❌ 不要 bring_to_front / 搶焦點
❌ 不要關它
✅ 驗證用的瀏覽器一律【獨立 profile】（--user-data-dir=%TEMP%\edge-verify-xxx）
✅ 用獨立埠（別人正在用的埠不要搶，挑 9300+ 沒人用的）
```

### 7.3 不要搬動他的遊戲視窗

```
⚠️ backroom-logger.ps1 的 -WinSize / -WinPos 是【預設值】，會搬他的視窗
✅ 要加 -NoResize
✅ 或錄它自己的視窗（-TitleMatch Wiki摄影机）
```

### 7.4 一個帳號只能跑一個 bot

```
⚠️ 自動玩已於 2026-10-21 移除，本條只剩歷史意義
❌ 同帳號開兩個實例 → 遊戲會踢（「這個帳號在別的裝置進了房間」）→ 結算卡住
```

## 第 8 條：檔案編碼

```
✅ .ps1 → UTF-8 with BOM（239,187,191）
   ⚠️ edit 工具會剝掉 BOM → 改完【一定要補回並驗證】
   今天已發生 3 次因 BOM 被剝而爆幾百個假語法錯誤
✅ .js / .html / .md → UTF-8 無 BOM
```

---

## 第 9 條：改完要【證明】

**回覆時要附**：
```
✅ before → after 的對照（檔名/大小/行數/色碼/文字）
✅ 實際執行輸出（不是「我改了」）
✅ 截圖路徑（自己先看過）
✅ grep 驗證（例如事件瀏覽器 UI 的「岔路」= 0 次；⚠ 全檔 grep 會有 65 次，那是樓層內容引用遊戲原文）
✅ 證明沒動到不該動的檔案（mtime / 雜湊）
❌ 不要只說「已完成」
```

**⚠️ 而且【誠實說做不到的】**：
```
✅ 「這 4 條路徑仍標（尚無資料），資料未收，沒編造」
✅ 「1280px 窄視窗會橫向溢出，那是既有佈局問題，不在本次範圍」
❌ 不要假裝全部做完
```

---

## 第 10 條：不要中途停

> **發生過**：agent 改到一半被中斷 → HTML 加了但 JS 沒跟上 → 整頁崩（`Uncaught`）

```
✅ 一次把一輪改動做完，再做驗證，最後回報
✅ 如果真的要分批，【先讓檔案保持可用狀態】再停
❌ 不要「我先加 HTML，等下再加 JS」然後就停
```

---

## 第 11 條：不要用 PowerShell 單引號組含引號的 JS

> **踩過兩次**：`''`（空字串）被 PowerShell 吃成 `'` → `SyntaxError: Invalid regular expression flags` → **整支 script 死掉**

```powershell
# ❌ 錯
$js = 'var x = arr.map(p => ''<li>'' + p + ''</li>'');'

# ✅ 對（here-string，literal）
$js = @'
var x = arr.map(p => '<li>' + p + '</li>');
'@

# ✅ 或（用 char 組引號）
$q = [char]39
$js = 'var x = arr.map(p => ' + $q + '<li>' + $q + ' + p + ' + $q + '</li>' + $q + ');'
```

**⚠️ 而且 `@" "@` 會展開 `$` 變數，`@' '@` 不會** —— 寫 JS 一律用後者。

---

## 第 12 條：Git / 無頭瀏覽器的坑

```
⚠️ 無頭 Edge 對 file:// 只改 hash【不會重載】→ 一直跑舊 JS
   → 先 about:blank，再帶 ?v=<時間戳> 重載
⚠️ 臨時測試腳本：用 require 就存 .cjs；用 import 就存 .mjs（不要混）
⚠️ Page.captureScreenshot 帶 clip 會【永久弄壞 viewport】→ 不要用 clip
⚠️ 在 UI 執行緒同步探測連接埠 → 介面假死（Windows 要等 2 秒才失敗）
   → 用 GetExtendedTcpTable 查 LISTEN
```

## 第 13 條：使用者的表達方式（**讀懂可以少走彎路**）

| 他說 | 意思是 |
|---|---|
| 「**跑偏了**」 | 立刻停下來，**實際渲染截圖**對照他的要求，不要繼續猜 |
| 「**可用个毛**」 | 你做的東西**根本沒達到要求**，要從根本重做 |
| 「**这不就是旧版**」 | 你改了但**使用者看不到效果** → 檢查快取／路徑／是不是改了另一個檔 |
| 「**先等等**」 | **不要再往下做**，先跟他對齊 |
| 「**请快点**」 | 你在問太多問題或在做不必要的事，**直接做** |
| 「**全开**」「**全力工作**」 | 放手做，不用省 token |
| 「**你自己做**」 | **不要派 agent**，你自己動手 |
| 「**我让你做在X里 你做哪里去了**」 | 你改錯檔案了 |
| 貼一張截圖 ＋ 箭頭 | 箭頭指向的位置是要改的地方，**箭頭顏色不代表配色** |
| 貼一張截圖 ＋ 圈 | 圈起來的是要改／要拿掉的東西 |

---

## 第 14 條：先問，但只問關鍵的

```
✅ 問【會影響方向的】問題（改哪個檔？外形要怎樣？範圍多大？）
❌ 不要問【自己能查到的】（檔案在哪、資料長怎樣 → 自己 grep / read）
✅ 一次問 1~3 個
❌ 不要列十個選項讓他選
```

---

## 第 15 條：文件要留

```
✅ 大改動完成後，寫交接文件（哪個檔、改了什麼、怎麼驗證、還沒做什麼）
✅ 規格變更要【當場更新】到交接文件裡
✅ 不要只在對話裡講 —— 對話會被壓縮，檔案不會
```
