# 规例 — 跟这位用户合作的方式

> **给任何 agent 的第一份必读文件。**
> 这不是技术文件，是**行为规则**。每一条都是实际被纠正过的，不要打折。
> 搭配 `交接.md`（项目现况）一起读；技术细节与踩坑记录看 `AGENTS.md`。
> （用户口语说的“规例.md”就是这个档。）

---

## 第 0 条：最重要的一条

> **用户说“设计示例”就是设计示例，说“真实站”就是真实站。**
> **改错文件是最严重的错误。**

**发生过**：用户要求“在 wiki 设计示例里”改事件浏览器，我派 agent 去改了真实站的 `build-site.ps1`（900 行）。
用户回：“**我让你做在wiki设计示例里 你做哪里去了**”。

### 规则

```
✅ 每次动手前，先确认要改的是哪个文件，并在回复里【明讲】
✅ 不确定就问一句“改 `_drafts\设计示例-我自己做.html` 还是 `build-site.ps1`？”
✅ 改完要证明【其他文件没动】（贴 mtime 或杂凑）
❌ 不要“顺手”把改动套到别的文件
❌ 不要“反正迟早要用”就自作主张
```

---

## 第 1 条：先约定外形，再动手

> **用户原话：“先等等 我们先约定事件浏览器的外形”**

```
✅ 大改动之前，先问清楚或先提方案（外形／布局／互动）
✅ 提出方案时用 ASCII 图或清楚的文字描述，让他能一眼看懂
✅ 他同意后才动手
❌ 不要自己先做一大堆，做完才让他看（他会说“跑偏了”）
```

**⚠️ 但也不要问太多**：一次问 **1~3 个关键问题**，不要列十个选项让他选。
（他有时会不耐烦：“**请快点**”）

---

## 第 2 条：截图上的箭头／圈／颜色，多半只是**标注**

> **用户原话：“不要用颜色啊啊啊 我只是用了这个颜色的箭头告诉你哪个是哪个 不是让你用那个颜色！！”**

```
❌ 他在截图上画的【箭头颜色、圈选颜色】通常只是【指出位置】，不是要你用的配色
✅ 要看的是“箭头指向哪里”，不是“箭头是什么颜色”
⚠️ 真的要用他的颜色时，他会明讲（例如“用 #FFC23D”）
```

**同理**：他圈的范围通常是“**这几个东西要改**”，不是“这个范围要保留”。

---

## 第 3 条：改完一定要**实际渲染**验证，不是只看语法

> **发生过**：`node --check` 过了（语法 OK），但 HTML 元素没插入，
> `getElementById(...).addEventListener` 抛 `TypeError` → **整支 script 死掉**
> → 页面空白／路径列表空／按钮不见。用户回：“**跑偏了**”。

```
✅ 语法检查（node --check / PowerShell AST）
✅ ⭐ 用无头浏览器【实际载入】→ 确认 JS 例外 = 0（不是只有语法 OK）
✅ ⭐ 【截图】自己先看一眼，确认画面是对的（不是只贴数据）
✅ 确认关键元素真的存在（querySelector 有结果、数量对）
❌ 不要只贴“node --check exit 0”就说做完了
```

**⚠️ 而且【自己先看截图】** —— 很多时候问题一眼就看得出来
（按钮掉到第二行、清单是空的、标题列挤爆）。

---

## 第 4 条：不要编造，缺就写“（尚无资料）”

```
✅ 缺资料 → 写“（尚无资料）”，并在回复里说“这几项没资料”
✅ 不确定 → 标“（推定）”或“⚠ 待确认”
❌ 不要用“大概”“应该是”填空
❌ ❌ 特别是【机率】和【数值】—— 没有证据就不要写数字
```

**⚠️ 样本过少不写机率**（既有规则）；有样本就带样本数，例如“约 1/3（样本 3 次）”。

---

## 第 5 条：玩家名 ≠ 角色名（**这条错了会被骂**）

```
❌ 玩家名一律移除 → 换成“<玩家>”或“你”
   例：加菲／狐天／白落／小枫／小猎／小狙／Wiki探索者
       狐跑跑／枪客猫／noodlesfox／夭狐／禾狐／文件员／探索者

✅ 角色名要保留
   诺亚／汤玛斯／光明／狐霖／雾狐／游魂／面狐／鹿其／阳／阴／米香／灰狼／
   星龙／呐豆／小猦／御影／库特斯／奈兹米／灵音／菟耳丝／鬼月／小罗／小樱／
   凤凰／神话／小霏／喵汰／银夕／雷夫／天雀／白桃／Tmatpd／红豆／十龙／懒狼

⚠️【天狐】与【O₂】已经是游戏内角色（2026-10-18 更新）→ 不要当玩家名删掉
⚠️ 判断方式：① 看角色面板 ② 去 `页面\09-角色名录.md` 查证
⚠️ 查不到 ≠ 不是角色 —— 可能是别名或名录还没收
⚠️ 不确定就【问用户】，不要自己判定成玩家名删掉
```

**面板判断法**：上方大字＝玩家账号名；下方小字＝`角色名｜称号`。
例：`天狐`（上）＋ `小猦｜画布中的执笔者`（下）→ 玩家“天狐”在玩角色“小猦”，
Wiki 写“小猦”或“你”；**不是**把“天狐”当文本、也**不是**把“小猦”删掉。

**字形陷阱**：`呐`/`纳`、`猦`/`猎`、`枫`/`枫`（繁简异体，比对时要同时试）

**⚠️ 同名陷阱**：“懒狼”**既是玩家账号名、也是一只角色名**（称号“向阳的细剑”）。
判断法：**属性总和 13 ＝ 固定角色；12 ＝ 自订角色**。

## 第 6 条：对话用**简体**，内容用**繁体**

> **用户原话：“我其实在江苏无锡 只是游戏默认繁体中文 请用简体和我说话”**

```
✅ 跟用户对话（回复、说明、提问、进度报告）→ 【简体中文】
✅ Wiki 页面内容、项目文件、脚本注解 → 【繁体中文】
✅ 游戏内文字 → 照抄（游戏默认繁体）
⚠️ 不要因为游戏是繁体，就假设他习惯繁体
```

## 第 7 条：程序红线（**违反会出人命**）

### 7.1 绝对不要用程序名称批量关程序

```powershell
# ❌❌❌ 全部禁止
Stop-Process -Name msedge
taskkill /IM chrome.exe
Get-Process xxx | Stop-Process
Get-Process node | Where-Object { $_.CommandLine -like '*adobe*' } | Stop-Process

# ✅ 只关自己启动、明确记下 PID 的
$p = Start-Process ... -PassThru
Stop-Process -Id $p.Id
```

**实际事故**：
```
2026-10-14：杀掉用户正在玩的 Edge 游戏
2026-10-17：用 -like '*路径关键字*' 误杀 Adobe 的 node
```

### 7.2 用户的 Edge 绝对不要碰

```
❌ 不要 bring_to_front / 抢焦点
❌ 不要关它
✅ 验证用的浏览器一律【独立 profile】（--user-data-dir=%TEMP%\edge-verify-xxx）
✅ 用独立埠（别人正在用的埠不要抢，挑 9300+ 没人用的）
```

### 7.3 不要搬动他的游戏窗口

```
⚠️ backroom-logger.ps1 的 -WinSize / -WinPos 是【默认值】，会搬他的窗口
✅ 要加 -NoResize
✅ 或录它自己的窗口（-TitleMatch Wiki摄影机）
```

### 7.4 一个账号只能跑一个 bot

```
⚠️ 自动玩已于 2026-10-21 移除，本条只剩历史意义
❌ 同账号开两个实例 → 游戏会踢（“这个账号在别的装置进了房间”）→ 结算卡住
```

## 第 8 条：文件编码

```
✅ .ps1 → UTF-8 with BOM（239,187,191）
   ⚠️ edit 工具会剥掉 BOM → 改完【一定要补回并验证】
   今天已发生 3 次因 BOM 被剥而爆几百个假语法错误
✅ .js / .html / .md → UTF-8 无 BOM
```

## 第 9 条：改完要【证明】

**回复时要附**：
```
✅ before → after 的对照（档名/大小/行数/色码/文字）
✅ 实际执行输出（不是“我改了”）
✅ 截图路径（自己先看过）
✅ grep 验证（例如事件浏览器 UI 的“岔路”= 0 次；⚠ 全档 grep 会有 65 次，那是楼层内容引用游戏原文）
✅ 证明没动到不该动的文件（mtime / 杂凑）
❌ 不要只说“已完成”
```

**⚠️ 而且【诚实说做不到的】**：
```
✅ “这 4 条路径仍标（尚无资料），资料未收，没编造”
✅ “1280px 窄窗口会横向溢出，那是既有布局问题，不在本次范围”
❌ 不要假装全部做完
```

## 第 10 条：不要中途停

> **发生过**：agent 改到一半被中断 → HTML 加了但 JS 没跟上 → 整页崩（`Uncaught`）

```
✅ 一次把一轮改动做完，再做验证，最后回报
✅ 如果真的要分批，【先让文件保持可用状态】再停
❌ 不要“我先加 HTML，等下再加 JS”然后就停
```

---

## 第 11 条：不要用 PowerShell 单引号组含引号的 JS

> **踩过两次**：`''`（空字串）被 PowerShell 吃成 `'` → `SyntaxError: Invalid regular expression flags` → **整支 script 死掉**

```powershell
# ❌ 错
$js = 'var x = arr.map(p => ''<li>'' + p + ''</li>'');'

# ✅ 对（here-string，literal）
$js = @'
var x = arr.map(p => '<li>' + p + '</li>');
'@

# ✅ 或（用 char 组引号）
$q = [char]39
$js = 'var x = arr.map(p => ' + $q + '<li>' + $q + ' + p + ' + $q + '</li>' + $q + ');'
```

**⚠️ 而且 `@" "@` 会展开 `$` 变数，`@' '@` 不会** —— 写 JS 一律用后者。

## 第 12 条：Git / 无头浏览器的坑

```
⚠️ 无头 Edge 对 file:// 只改 hash【不会重载】→ 一直跑旧 JS
   → 先 about:blank，再带 ?v=<时间戳> 重载
⚠️ 临时测试脚本：用 require 就存 .cjs；用 import 就存 .mjs（不要混）
⚠️ Page.captureScreenshot 带 clip 会【永久弄坏 viewport】→ 不要用 clip
⚠️ 在 UI 执行绪同步探测连接埠 → 界面假死（Windows 要等 2 秒才失败）
   → 用 GetExtendedTcpTable 查 LISTEN
```

## 第 13 条：用户的表达方式（**读懂可以少走弯路**）

| 他说 | 意思是 |
|---|---|
| “**跑偏了**” | 立刻停下来，**实际渲染截图**对照他的要求，不要继续猜 |
| “**可用个毛**” | 你做的东西**根本没达到要求**，要从根本重做 |
| “**这不就是旧版**” | 你改了但**用户看不到效果** → 检查快取／路径／是不是改了另一个档 |
| “**先等等**” | **不要再往下做**，先跟他对齐 |
| “**请快点**” | 你在问太多问题或在做不必要的事，**直接做** |
| “**全开**”“**全力工作**” | 放手做，不用省 token |
| “**你自己做**” | **不要派 agent**，你自己动手 |
| “**我让你做在X里 你做哪里去了**” | 你改错文件了 |
| 贴一张截图 ＋ 箭头 | 箭头指向的位置是要改的地方，**箭头颜色不代表配色** |
| 贴一张截图 ＋ 圈 | 圈起来的是要改／要拿掉的东西 |

## 第 14 条：先问，但只问关键的

```
✅ 问【会影响方向的】问题（改哪个档？外形要怎样？范围多大？）
❌ 不要问【自己能查到的】（文件在哪、资料长怎样 → 自己 grep / read）
✅ 一次问 1~3 个
❌ 不要列十个选项让他选
```

## 第 15 条：文件要留

```
✅ 大改动完成后，写交接文件（哪个档、改了什么、怎么验证、还没做什么）
✅ 规格变更要【当场更新】到交接文件里
✅ 不要只在对话里讲 —— 对话会被压缩，文件不会
```
