# 事件與日誌結構規範（重要交接文件）

> 這份文件是依照使用者逐段說明的遊戲實際畫面整理的**事件結構正本**。
> 目的：讓後續接手的 agent 不需要重新猜事件邊界，也不會再把路口、事件、樓層介紹混在一起。
>
> 目前狀態：Wiki 內所有舊事件紀錄已先全部移除（`EVB_NODES = {}`、動態事件節點停用、樓層 `_events`/`AUTO-EVENTS` 已清空）。
> **在依本文件重做 parser 並通過範例驗證之前，不要把事件資料重新寫回正式 Wiki。**

---

## 0. 一句話總結

```text
樓層 transition
  → 樓層標題／樓層介紹
  → 玩家角色台詞
  → 路口（路口文本＋路徑選項）
  → 事件（事件名＋事件介紹＋行動選項）
  → 判定／結果／效果
  → 看完按「繼續」
  → 出口進度 +1
  → 下一個路口
```

樓層出口事件是另一個獨立事件；完成本層所需事件後，通常會強制進入出口事件。

## 1. 樓層相關

### 1.1 切層黑屏

切換樓層時，畫面固定全黑，中央顯示樓層名。

正常第一次到未知樓層：

```text
Level ???
(???)
```

已知道樓層名時（例如被動／後室百科／已探索）：

```text
Level 0.41
(病)
```

特殊樓層：

```text
The Void「虛空」
```

分類：

```text
floor.transition.title
floor.transition.subtitle
```

這不是樓層介紹，也不是事件正文。

### 1.2 樓層名何時顯示

- 正常第一次到某層：顯示 `???`
- 走過該層一半進度後：才顯示真實樓層名
- 隊伍有特殊被動：進入時可直接看到名字
- `後室百科`：進入時直接知道樓層名，切層黑屏就直接顯示真實名稱

因此樓層名一定要有「已知／未知」與「揭示來源」：

```text
floor.known = true | false
floor.revealSource =
  unknown
  progress
  passive:後室百科
  ability
```

### 1.3 頂部 HUD 樓層名

遊戲畫面頂部會顯示：

```text
Level 0.01「出口?」
第 2 層｜距離：入口附近｜岔路
```

或：

```text
Level 161「阿帕拉契的荒涼」
第 2 層｜1980 年 1 月｜區域：樹林｜岔路
```

分類：

```text
floor.title
floor.meta
```

注意：

- `第 N 層` 是**本局樓層計數**，不是 `Level N`。
- `floor.title` 和正文中的 `floor.header` 可能不一致。
- 例如頂部已顯示 `Level 161「阿帕拉契的荒涼」`，正文仍可能是 `—— Level ???「???」 ——`。
- 這兩個欄位要分開記錄，不能互相覆蓋。

### 1.4 正文樓層標題

正文中的黃色標題線：

```text
—— Level 161「阿帕拉契的荒涼」 ——
```

未知時：

```text
—— Level ???「???」 ——
```

分類：

```text
floor.header
```

### 1.5 角色開場文本

本局剛開始、角色第一次進入遊戲時，紅框區域會有一段角色開場文字。

例：

```text
切出現實
前一秒，你還站在原地的地方——天狐盯着一面泛黄的牆紙研究了很久，想弄懂它為什麼會這麼黃——再抬起頭的時候，四周全是一樣的牆紙。
下一秒，腳下的地板好像突然消失了，整個人往旁邊一滑。
回過神來，你已經摔在一片濕濕的地毯上。四周是發霉的黃色壁紙，頭頂的日光燈嗡嗡嗡地響個不停。
四周一個人也沒有。天狐小聲地問了一句，也不知道是在問誰：「……這裡是哪裡？」
```

規則：

- 只在本局開始時出現
- 通常不會往上翻特意去看
- **不是樓層介紹**
- 不進 `floor.intro`

分類：

```text
character.intro
```

### 1.6 樓層介紹

黃框區域是當前樓層名＋樓層介紹。

例：

```text
—— Level 0「大廳」 ——
單調的黃色壁紙、潮濕的地毯、到處都是的電源插座，還有頭頂那永遠不會停的日光燈嗡嗡聲，比一般的日光燈吵得多，吵到太陽穴一跳一跳地痛。
這裡的每一個房間都長得差不多，卻沒有兩個完全一樣。你試著走直線，回頭時卻發現身後已經換成了另一組房間。
一個人也沒有，除了嗡嗡聲，什麼都聽不到。待久了，連自己的腦袋都開始不太可靠。
```

規則：

- `floor.intro` 只收樓層／環境介紹
- **不要記錄玩家角色說的話**
- 角色台詞、能力揭示、系統結算都不能混進 `floor.intro`

### 1.7 玩家角色台詞

綠色／金色文字：

```text
天狐：「好熱，燈又閃得好凶。我的眼睛在申請下班。」
```

結構：

```text
玩家名：該玩家選擇的角色說的話
```

分類：

```text
dialogue.player
```

欄位：

```text
speakerRaw     畫面上的玩家名，例如「天狐」
text           引號內的角色台詞
```

Wiki 正式內容要依 `AGENTS.md` 的玩家名／角色名規則處理；原始 log 保留 `speakerRaw`，不要直接刪。

### 1.8 能力／圖鑑揭示

紫色文字，例如：

```text
天狐在心裡翻到這一頁：Level 0.01「出口?」。
```

或：

```text
天狐一眼就認出來了：這裡是 Level 161「阿帕拉契的荒涼」。
```

分類：

```text
ability.reveal
```

規則：

- 這不是通用樓層介紹
- 只有部分角色／能力會有
- `後室百科` 通常直接在切層黑屏與正文標題顯示真名，**不會**再出現紫色揭示句
- 不能把紫色句當成所有樓層的固定欄位

### 1.9 後室百科與一般被動的差異

使用者實例：

| 情況 | 切層黑屏 | 正文標題 | 紫色揭示句 |
|---|---|---|---|
| 一般角色、未知樓層 | `Level ???` `(???)` | `—— Level ???「???」 ——` | 可能有 |
| 带后室百科 | `Level 0.41` `(病)` | `—— Level 0.41「病」 ——` | 沒有 |
| 其他洞察能力 | 可能仍 `???` | 可能仍 `???` | 可能有 |

所以 parser 不能假設「紫色句一定存在」，也不能假設「頂部有真名，正文就一定有真名」。

## 2. 路口（Junction）

### 2.1 定義

路口是「選擇要往哪裡走」的地方。

固定提示：

```text
要走哪條路？
```

事件內部的行動提示則是：

```text
要怎麼做？
```

兩者不可混。

### 2.2 路口文本

路口提示前面的最後一段白字，是路口文本。

例：

```text
一直往下掉。也可能是往上。這裡沒有方向。
```

例：

```text
沒有聲音。連自己的呼吸聲，都好像被什麼吸走了。
```

例：

```text
樹林安靜得不自然——沒有鳥，沒有蟲。
```

分類：

```text
junction.text
```

**這不是 `event.story`。**

### 2.3 路口前可能先有角色台詞

順序可能是：

```text
junction.text
dialogue.player
junction.prompt
```

例：

```text
沒有聲音。連自己的呼吸聲，都好像被什麼吸走了。
天狐：「好黑……論壇上說黑的地方要特別小心。」
要走哪條路？
```

角色台詞仍記 `dialogue.player`，不是路口文本。

### 2.4 路口路徑

例：

```text
要走哪條路？
- 伸手往黑暗裡抓
- 往更深的地方沉
- 讓身體自己轉
  （只有你察覺到）你隱約聽見那邊有聲音——不是腳步聲，比較像是有什麼東西在運轉。
  [說出來]
```

分類：

```text
junction.prompt
junction.paths[]
```

每個 path：

```text
path.text
path.perception = true | false
path.hint
path.hintKind
path.announce
```

### 2.5 感知提示（可出現在任何路徑）

感知不是一種獨立的路徑類型。

任何一條 `junction.path` 都可能在玩家感知足夠時，額外顯示一段提示，告訴玩家這條路**可能通向什麼類型的事件**。

例：

```text
（只有你察覺到）那邊好像有什麼不尋常的東西在等著。
```

例：

```text
（只有你察覺到）你隱約聽見那邊有聲音——不是腳步聲，比較像是有什麼東西在運轉。
```

例：

```text
跟著火把走
（只有你察覺到）你聽見那邊有很慢很慢的流水聲。
```

規則：

- 感知提示是掛在 path 上的附加欄位，不是把 path 改成另一種類型。
- 可能 0 條、1 條、多條 path 同時有提示。
- 這只是**模糊類型提示**
- 不是事件名
- 不是事件正文
- 不可自行補成「機械事件」或某個具體事件
- 可以記粗略 `path.hintKind`，但要標低信心
- 右邊「說出來」是分享情報的 UI，不是 path 文本

```text
path.perception = true
path.hint = 原始提示
path.hintKind = 聲音 / 機械運轉（模糊）
path.announce = true
```

### 2.6 選中路徑

選中路徑後，日誌會出現：

```text
→ 你決定：「伸手往黑暗裡抓」
```

分類：

```text
path.selected
```

這一行是「已選路徑」，不是事件名，也不是新的路口。

### 2.7 路徑數量不固定

可能是：

```text
2 個
3 個
```

不要寫死。

### 2.8 多數決 UI

```text
跟隨多數：關
```

是 UI，不進 log。

## 3. 事件（Event）

### 3.1 事件開始

選完路徑後進入事件。

事件名用 `【】` 包住：

```text
【一個顏色】
```

分類：

```text
event.name = 一個顏色
```

### 3.2 頂部事件列

進入事件後，頂部樓層列會由區域變成事件名：

```text
第 3 層｜一個顏色
```

分類：

```text
event.meta
```

規則：

- 事件名可能和頂部這行重複，只記一次 `event.name`
- 頂部這行有時還會塞難度、樓層特殊機制
- **不要和 `floor.meta`／區域混淆**
- 事件結束後，頂部應回到區域／岔路

### 3.3 事件介紹

```text
什麼都看不到。你試著想一個顏色——
黑暗裡，好像真的浮出了一點點那個顏色。很淡、很淡。
```

分類：

```text
event.intro
```

### 3.4 事件提示

```text
要怎麼做？
```

分類：

```text
event.prompt
```

不是 `要走哪條路？`。

### 3.5 事件行動

例：

```text
- 一直想著它，讓它變大
  智力 難度 12
- 看著它消失
```

分類：

```text
event.actions[]
```

每個 action：

```text
action.text
action.check.attribute
action.check.hasCheck
action.check.difficulty = variable（不記實際數字）
```

### 3.6 判定

例：

```text
（智力 難度 12）天狐 擲出 17+6=23 → 成功
```

分類：

```text
action.selected
check.attribute
check.outcome
```

**硬性規則：不要記錄具體難度數字，也不要記錄骰值。**

原因：不同遊戲難度、探索進度、隊伍狀態下，判定難度差異極大，記固定數字會誤導。

只記：

```text
check.attribute = 智力
check.hasCheck = true
check.outcome = success | failure
check.difficulty = variable
check.roll = 不記錄
```

### 3.7 結果

成功分支例：

```text
那個顏色慢慢變大，大得像一扇門。你朝它划過去。它沒有消失。
```

分類：

```text
result.text
```

成功／失敗是不同分支，不可合併成同一個 result。

```text
event.action
  check
    success → result.success
    failure → result.failure
```

### 3.8 效果

例：

```text
天狐：經驗 +1
```

分類：

```text
result.effects[]
```

例：

```text
effects = [
  { target: 天狐, kind: 經驗, amount: 1 }
]
```

不要只把「經驗 +1」塞進 result 文字，效果要獨立欄位。

### 3.9 事件完成

結果下方：

```text
看完之後按「繼續」
[繼續] (0/1 人看完了)
```

`繼續` 是事件結束確認，不是事件內容，也不是路口。

按下繼續後：

```text
event.completed = true
```

**事件不是結果一出現就結束；要按繼續才結束。**

## 4. 出口進度與出口事件

事件完成後會出現：

```text
出口進度 1/5
```

分類：

```text
floor.progress.current = 1
floor.progress.total = 5
```

代表：

- 本層已完成 1 個事件
- 本層需要完成 5 個事件

完成所有事件後，會進入**出口事件**，把玩家送到其他樓層。

規則：

- 出口事件通常是**強制**的
- 大部分樓層允許最多額外探索 2 個事件
- `The Void` 不允許額外事件
- 出口事件本身要算獨立事件，不要併進最後一個普通事件

```text
floor.exitEvent.started
floor.exitEvent.forced = true
floor.extraEventsAllowed = 2（大部分樓層）
The Void：0
```

## 5. 事件生命週期（狀態機）

```text
floor_transition
  ↓
floor_header / floor_intro
  ↓
dialogue.player（可選）
  ↓
junction
  ├─ junction.text
  ├─ dialogue.player（可選）
  ├─ junction.prompt
  └─ junction.paths[]
       ↓ 選中路徑
path.selected
  ↓
event
  ├─ event.name
  ├─ event.meta
  ├─ event.intro
  ├─ event.prompt
  └─ event.actions[]
       ↓ 選中行動
action.selected
  ↓
check（可選）
  ↓
result.success / result.failure
  ↓
result.effects[]
  ↓
看完按繼續
  ↓
event.completed
  ↓
floor.progress +1
  ↓
下一個 junction
```

若本層事件完成數達到 total：

```text
floor.exitEvent
  ↓
切層黑屏
  ↓
下一層
```

## 6. 文字顏色與畫面位置

### 6.1 顏色是輔助，不是唯一依據

不同樓層有自己的配色，同一個顏色在不同樓層可能代表不同東西。

例：

- 紅色可能是樓層標題
- 紅色也可能是危險提示或受傷
- 黃色可能是樓層標題線、路口提示或選項
- 白色可能是樓層介紹、路口文本或事件正文

**分類必須同時看：顏色＋區域＋前後文。**

### 6.2 目前觀察到的常見對應

```text
紅色／橙紅     樓層標題、區域資訊、危險提示、系統結算
橙色           系統結算、轉場結算
紫色           能力／圖鑑／洞察揭示
黃色           正文樓層標題線、路口提示、選項
綠色／金色     玩家角色台詞
白色           樓層介紹、路口文本、事件正文、結果
灰色／淺灰     次要說明、條件、補充
```

### 6.3 以位置與錨點分類

優先使用固定文字錨點：

```text
Level ??? / Level N         → floor.transition 或 floor.title
—— ... ——                   → floor.header
要走哪條路？                → junction.prompt
要怎麼做？                  → event.prompt
看完之後按「繼續」          → event.completed
出口進度 N/M                → floor.progress
【事件名】                  → event.name
→ 你決定：「...」            → path.selected / action.selected
（... 難度 ...）... → 成功   → check
```

### 6.4 重複文本

同一句角色台詞可能同時出現在：

- 正文綠色台詞行
- 畫面中間／右上角漂浮氣泡

只記一條 `dialogue.player`；氣泡不另記。

## 7. 日誌 JSONL 建議格式

以下只是結構建議，實際檔名／欄位可調，但**語義必須保留**。

```json
{"ts":"...","type":"floor_transition","floorId":"0.41","name":"病","known":true,"revealSource":"passive:後室百科"}
{"ts":"...","type":"floor_title","floorId":"0.41","title":"Level 0.41「病」","meta":"第 3 層｜區域：腐爛的大廳｜岔路"}
{"ts":"...","type":"floor_header","floorId":"0.41","text":"—— Level 0.41「病」 ——"}
{"ts":"...","type":"floor_intro","floorId":"0.41","text":"黃色的大廳，可是不對。……"}
{"ts":"...","type":"dialogue","speaker":"天狐","text":"好、好安靜……我聽得到自己的心跳。"}
{"ts":"...","type":"junction","floorId":"0.41","text":"一直往下掉。也可能是往上。這裡沒有方向。","prompt":"要走哪條路？","paths":[{"text":"往更深的地方沉","perception":false},{"text":"伸手往黑暗裡抓","perception":true,"hint":"那邊好像有什麼不尋常的東西在等著","announce":true}]}
{"ts":"...","type":"path_selected","text":"伸手往黑暗裡抓"}
{"ts":"...","type":"event","floorId":"0.41","name":"一個顏色","meta":"第 3 層｜一個顏色","intro":"什麼都看不到。你試著想一個顏色——…","prompt":"要怎麼做？"}
{"ts":"...","type":"action_selected","text":"一直想著它，讓它變大"}
{"ts":"...","type":"check","attribute":"智力","hasCheck":true,"outcome":"success","difficulty":"variable","roll":null}
{"ts":"...","type":"result","branch":"success","text":"那個顏色慢慢變大，大得像一扇門。你朝它划過去。它沒有消失。"}
{"ts":"...","type":"effect","target":"天狐","kind":"經驗","amount":1}
{"ts":"...","type":"event_completed","eventName":"一個顏色"}
{"ts":"...","type":"progress","current":1,"total":5}
```

### 7.1 不要寫入的欄位

```text
check.difficulty 的實際數字
check.roll 的實際骰值
check.bonus 的實際加值
```

可以保留：

```text
check.hasCheck
check.attribute
check.outcome
check.difficulty = "variable"
```

### 7.2 必須保留的來源

```text
rawText         OCR 原文
source          ocr / manual
confidence      OCR 信心
frame/session   哪一幀、哪一場
```

寧可保留低信心 raw，也不要猜一個錯的事件。

## 8. 樓層／事件邊界規則

### 8.1 新樓層開始

```text
切層黑屏
→ floor_transition
→ 樓層標題／介紹
```

### 8.2 事件開始

```text
path.selected
→ 【事件名】
→ event.name
```

### 8.3 事件結束

```text
看完之後按「繼續」
→ event.completed
```

### 8.4 下一個路口

```text
event.completed
→ 出口進度 N/M
→ junction.text
→ 要走哪條路？
```

### 8.5 不可跨越邊界合併

不可把：

```text
上一段 event.result
+ 系統結算
+ 新樓層 floor.intro
```

合併成同一段。

也不可把：

```text
路口文本
+ 事件名
+ 事件介紹
```

合併成同一事件。

## 15. 追加實例：The Void 的五個事件（無判定／成功／失敗）

以下四個畫面補齊了「事件不一定有判定」與「失敗分支」的情況。

### 15.1 出口進度

`出口進度 N/M` 是事件完成後的層內進度，不是路口或事件正文。

```text
event.completed
→ floor.progress.current += 1
```

當看到：

```text
出口進度 5/5
```

代表本層普通事件已完成，接下來會進入**出口事件**（通常強制）。

---

### 15.2 無判定事件：`【背後】`

畫面順序：

```text
出口進度 1/5
junction.text = 沒有聲音。連自己的呼吸聲，都好像被什麼吸走了。
dialogue.player = 天狐：「好黑……論壇上說黑的地方要特別小心。」
path.selected = → 你決定：「讓身體自己轉」

event.name = 背後
event.intro =
背後好像有什麼。
不是聲音，也不是看到，是一種「有東西在」的感覺。很近，就在伸手碰得到的地方。

action.selected = → 你決定：「猛地回頭」
result.text =
回頭。什麼都沒有。黑暗。轉回來——也是黑暗。分不清楚剛剛是回頭了，還是轉了一整圈。
effect = 天狐：理智 -1
出口進度 2/5
```

重點：

- 這個事件沒有 check
- `action.selected` 後直接 result
- result 後直接 effect
- 不可因為沒有「成功／失敗」就漏記整個事件

```text
action.check.hasCheck = false
result.text = ...
result.effects = [{ target:"天狐", kind:"理智", amount:-1 }]
```

---

### 15.3 成功分支：`【飄過去的回憶】`

```text
出口進度 2/5
junction.text = 一直往下掉。也可能是往上。這裡沒有方向。
path.selected = → 你決定：「往記得的方向掉」

event.name = 飄過去的回憶
event.intro =
黑暗裡，有一段回憶從旁邊飄過去。
不是看到，是想起來。一個夏天的下午、一張舊沙發、電風扇的聲音。好像是你的，又好像不是。

action.selected = → 你決定：「伸手抓住它」
check = （感知 難度 11）天狐 擲出 19+4=23 → 成功
result.text =
你抓住了。是你的——你小時候的家，沙發上有一個被你燒出來的小洞。你都忘了有那個洞。現在想起來了。
effect = 天狐：理智 +1
出口進度 3/5
```

只記：

```text
check.attribute = 感知
check.outcome = success
check.difficulty = variable
check.roll = null
```

不記 `難度 11`、`19+4=23`。

---

### 15.4 失敗分支：`【掉了多久】`

```text
出口進度 3/5
dialogue.player = 天狐：「看不到自己的手……好可怕。」
path.selected = → 你決定：「往更深的地方沉」

event.name = 掉了多久
event.intro =
你開始數。一、二、三……
數到一百多的時候，突然不確定自己剛剛數到哪裡。說不定已經數了好幾千次。說不定一次都沒有開始。

action.selected = → 你決定：「從頭再數一次，數得慢一點」
check = （智力 難度 12）天狐 擲出 3+6=9 → 失敗
result.text =
數到一半，數字自己跑掉了。你數到的最後一個數字是「好久」。
effect = 天狐：理智 -1
出口進度 4/5
```

重點：

- 失敗分支和成功分支結構相同
- 只是 `check.outcome = failure`，result 文字不同
- 不要把失敗結果丟掉，也不要把失敗記成成功

---

### 15.5 無判定＋技能式行動：`【一個名字】`

```text
出口進度 4/5
junction.text = 四周全黑。不是暗，是黑，像閉著眼睛，可是眼睛明明張著。
path.selected = → 你決定：「往更深的地方沉」

event.name = 一個名字
event.intro =
黑暗裡，你突然想不起一個人的名字。
是一起走的人。一路上叫過很多次的名字。第一個字還在，後面的……像沙子一樣一直漏掉。

action.selected = → 你決定：「記性好的人，把一路上發生的事從頭想一遍」
（無 check）
result.text =
天狐 從掉進來的那一刻往回翻：上一層、上上一層、第一個遇到的人、第一次一起吃的東西……每一件都想起來了。名字一個都沒有漏掉。
effect = 天狐：理智 +1
dialogue.player = 天狐：「口好渴……杏仁水，還有杏仁水嗎？」
status = 口渴 3
出口進度 5/5
```

重點：

- 行動可能沒有數值判定，而是靠角色能力／描述直接成功
- 仍記 `action.check.hasCheck = false`
- `（口渴 3）` 是狀態，不是台詞內容
- 台詞與狀態分開：

```text
dialogue.player.text = 口好渴……杏仁水，還有杏仁水嗎？
status.thirst = 3
```

- `出口進度 5/5` 代表普通事件結束，下一步是出口事件，不是再普通路口

---

### 15.6 `→ 你決定` 的兩種意思

同一個前綴有兩種角色：

#### 路徑選擇

```text
→ 你決定：「往更深的地方沉」
【事件名】
```

下一行是 `【事件名】` → `path.selected`。

#### 事件行動選擇

```text
→ 你決定：「猛地回頭」
（判定／結果）
```

下一行是 check、result 或效果 → `action.selected`。

Parser 必須看**下一行**，不能只看 `→ 你決定`。

---

### 15.7 事件後的台詞與狀態

事件結果／效果後面仍可能出現玩家台詞：

```text
effect
dialogue.player
status
出口進度
```

例：

```text
天狐：理智 +1
天狐：「口好渴……杏仁水，還有杏仁水嗎？」（口渴 3）
出口進度 5/5
```

不可把這句台詞算進 result，也不可把 `口渴 3` 算進台詞文字。

---

### 15.8 五事件結構總表

| 進度 | 事件 | 判定 | 結果 | 效果 |
|---|---|---|---|---|
| 1/5 → 2/5 | 背後 | 無 | 回頭什麼都沒有 | 理智 -1 |
| 2/5 → 3/5 | 飄過去的回憶 | 感知，成功 | 抓住回憶 | 理智 +1 |
| 3/5 → 4/5 | 掉了多久 | 智力，失敗 | 數字跑掉 | 理智 -1 |
| 4/5 → 5/5 | 一個名字 | 無／角色能力 | 想起名字 | 理智 +1、口渴 3 |
| 5/5 | 出口事件 | 未說明 | 未說明 | 未說明 |

`【背後】` 與 `【一個名字】` 證明：

```text
事件可以沒有擲骰
事件可以不顯示成功／失敗
但事件仍然有 event.name / event.intro / action / result / effect
```

## 16. 出口事件：`【光】`

出口事件不是普通路口，也不是普通事件；它是完成本層普通事件後**強制**進入的事件。

### 16.1 畫面順序

```text
floor.progress = 5/5

exit.lead =
走了這麼久，出口應該就在附近了。

dialogue.player =
天狐：「可以用手機的手電筒嗎？……電量只剩一點點。」

exit.signal =
空氣變了——這一層走到盡頭了。

event.name = 光
event.kind = exit
event.forced = true

event.intro =
下面有光。越來越近、越來越亮——亮到眼睛發痛。
風回來了，聲音回來了，往下掉的感覺一下子變得好真實。

event.prompt = 要怎麼做？

event.actions = [
  {
    text: 放手，讓它帶你去,
    forced: true
  }
]

action.selected =
→ 你決定：「放手，讓它帶你去」

result.text =
光一下子撲了上来。你從天花板上摔了下來，摔在一片真的、硬硬的地上。

system.transition =
(走出了這一層——這段路的記憶留了下來：你的記憶碎片 +3)
已經走過 3 層了——你：經驗 +3

floor.header = —— Level 0「大廳」——
floor.intro = 單調的黃色壁紙、潮濕的地毯……
dialogue.player = 天狐：「冷靜……文章說，第一步是不要慌。」
```

### 16.2 規則

- `出口進度 5/5` 代表普通事件已完成，接著才是出口事件。
- 出口事件仍然是 `event`，有名稱 `【光】`。
- 出口事件通常只有一個強制行動：

```text
event.actions.length = 1
event.actions[0].forced = true
```

- 沒有 `要走哪條路？`，也沒有普通 `junction.paths`。
- `走了這麼久，出口應該就在附近了。` 是出口事件的前導文本，不是樓層介紹。
- `空氣變了——這一層走到盡頭了。` 是出口訊號，不是事件正文。
- 出口結果之後才是：
  - 系統結算（記憶碎片、經驗）
  - 下一層的樓層標題
  - 下一層的樓層介紹
  - 下一層的角色台詞

### 16.3 不可混淆

```text
出口事件【光】
≠ 下一層的 floor.intro
≠ 普通路口
≠ 普通事件【…】
```

`【光】` 的結果是「摔到下一層」，不是下一層介紹。

### 16.4 記錄欄位

```text
exitEvent.started = true
exitEvent.forced = true
exitEvent.name = 光
exitEvent.lead
exitEvent.signal
exitEvent.intro
exitEvent.action
exitEvent.result
exitEvent.completed
```

出口事件完成後，才開始記下一層：

```text
floor.transition
floor.title
floor.header
floor.intro
dialogue.player
```

## 17. 出口事件後的新樓層

圖中 `【光】` 之後直接出現：

```text
Level 0「大廳」
單調的黃色壁紙……
天狐：「冷靜……文章說，第一步是不要慌。」
```

這些全部屬於**下一層**，不是出口事件的結果：

```text
floor.header = Level 0「大廳」
floor.intro = 單調的黃色壁紙……
dialogue.player = 天狐：「冷靜……文章說，第一步是不要慌。」
```

因此 parser 必須在 `exitEvent.result` 後切邊界：

```text
exitEvent.result
→ system.transition
→ floor.transition / floor.header
→ floor.intro
→ dialogue.player
```

不可把下一層的 `floor.intro` 接到出口事件 `【光】` 的 result 裡。

## 18. 出口事件的另一種樣貌：可延後離開

第 16 節的 `【光】` 是「只有一個強制行動」的出口事件；這一節補上另一種更常見的出口事件：

```text
【出口的門】
要怎麼做？
- 推開綠色的出口門
- 把手伸進那個洞，拉開門
- 先不走，再多探索幾步
```

### 18.1 出口事件不是固定只有一個行動

```text
event.kind = exit
event.actions = [
  { text: 推開綠色的出口門, kind: exit },
  { text: 把手伸進那個洞，拉開門, kind: exit_alt },
  { text: 先不走，再多探索幾步, kind: explore_more }
]
```

- `exit` / `exit_alt`：真正的出口
- `explore_more`：先不離開，回去探索額外事件
- 這個第三選項是**絕大多數樓層出口事件的常見類型**

所以「出口事件通常強制」要精確寫成：

```text
出口事件最終是強制的
但玩家可以用「先不走，再多探索幾步」延後
```

`The Void` 沒有額外事件，所以它的 `【光】` 只有一個強制行動。

### 18.2 選擇「先不走」的結果

```text
action.selected = → 你決定：「先不走，再多探索幾步」
result.text =
你決定先不走。出口就在旁邊，晚點再回來就好。這一層還有些地方沒看過，先去繞繞吧。
dialogue.player = 天狐：「好想喝飲料……冰的。」
status = 口渴 2
floor.progress = 7/7
```

之後進入新的探索場景，出口事件暫時結束；探索完再回到出口。

不可把「先不走」記成：

```text
path.selected
junction
樓層切換
```

它是**出口事件內的一個行動**。

### 18.3 沒有額外路可探索時

畫面會出現：

```text
這一層再也找不到別的路了。要從哪裡離開？
```

這是出口事件的**無額外路提示**，不是普通路口。

```text
exit.promptNoMore = 這一層再也找不到別的路了。要從哪裡離開？
```

此時只剩真正的出口行動：

```text
- 推開那扇綠色的出口門
- 推開那扇還沒裝門把的門
```

### 18.4 出口選項可能帶感知揭示

```text
推開那扇還沒裝門把的門
（只有你察覺到）你讀過的資料裡提過這種地方——這裡通往 Level 0「大廳」。
```

這次不是模糊類型，而是**具體目的地揭示**：

```text
action.kind = exit_alt
action.hint = 你讀過的資料裡提過這種地方——這裡通往 Level 0「大廳」。
action.revealedDestination = Level 0「大廳」
action.hintSource = 讀過的資料 / 感知
```

仍要保留 hint 原文，不能只寫目的地。

### 18.5 房間／場景列

```text
—— 房間：忽冷忽熱 ——
```

或：

```text
—— 房間：還算正常 ——
```

分類：

```text
scene.name
```

這不是 `floor.header`，也不是 `event.name`。

### 18.6 出口事件中的進度

```text
出口進度 +1
出口進度 7/7
```

- 前者是本次事件完成的增量提示
- 後者是當前總進度
- 不要重複加總，也不要記成 8/7

### 18.7 出口事件完整狀態

```text
exitEvent
  name = 出口的門
  actions[
    exit
    exit_alt
    explore_more
  ]
  ├─ 選 explore_more
  │    → result
  │    → 新探索場景
  │    → 探索事件
  │    → 回到出口
  │    → 再次顯示出口選項
  └─ 選 exit / exit_alt
       → result
       → 系統結算
       → 下一層
```

## 19. 出口事件與普通事件的差異

| 項目 | 普通事件 | 出口事件 |
|---|---|---|
| 名稱 | `【事件名】` | `【出口的門】` / `【光】` |
| prompt | `要怎麼做？` | `要怎麼做？`／`要從哪裡離開？` |
| 行動 | 一般行動 | 真出口／替代出口／先不走 |
| 是否可延後 | 不一定 | 可以，選 `explore_more` |
| 完成後 | 出口進度 +1 | 切到下一層 |
| 額外探索 | 樓層有上限 | 大多數樓層最多 2 個額外事件；Void 0 |

---

## 20. 修正第 16 節的「只有一個強制行動」

第 16 節的 `【光】` 仍然有效，但只代表 **The Void 這種沒有額外事件的出口**。

一般樓層的出口事件要按第 18 節處理：

```text
event.kind = exit
event.actions 可以有多個
其中一個是 explore_more
```

不可再把「出口事件只有一個行動」寫成全域規則。

## 21. 出口 → 新樓層的邊界實例（Level 27「木之荒蕪」）

畫面順序：

```text
scene.end =
這一間的燈是亮的，門是好的，溫度剛剛好。難得。
你繞來繞去，最後只剩下出口。

exit.action.selected =
→ 你決定：「推開那扇綠色的出口門」

exit.result =
門後面是一條木頭的走廊，又舊又暗，牆板發黑，地板嘎吱嘎吱響。牆的後面，好像有人在敲。

system.transition =
(走出了這一層——這段路的記憶留了下來：你的記憶碎片 +4)
已經走過 5 層了——你：經驗 +5

floor.header = —— Level 27「木之荒蕪」——

floor.intro =
木頭。牆是木板、天花板是木板、地上是木地板，鋪著一條灰灰的地毯。
木頭很舊，舊得發黑，有些地方爛得軟軟的，一按就陷下去。空氣很悶，灰塵在昏暗的燈光裡慢慢地飄。
天狐咳了一聲，又咳了一聲。
牆的後面，好像有人在輕輕地敲。叩、叩、叩。

dialogue.player =
天狐：「咳……好多灰塵……」

junction.text =
一條彎彎曲曲的木頭走廊，地板每踩一步就吱一聲。

junction.prompt = 要走哪條路？
junction.paths = [
  { text: 走進一間比較乾燥的木頭房間, perception: false },
  { text: 往那塊地毯鼓起來的地方走, perception: false }
]
```

規則：

- `exit.result` 雖然描述「木頭走廊」，仍然是出口事件結果，不是 `floor.intro`。
- 新樓層從 `—— Level 27「木之荒蕪」——` 才開始。
- 第三人的角色動作描寫（`天狐咳了一聲`）可以留在 `floor.intro`，但角色台詞（綠色 `天狐：「…」`）要另外記 `dialogue.player`。
- 出口結果與新樓層介紹可能有相似意象（都提到牆後有人敲），但**不是同一句**，不要跨段去重。
- `第 6 層` 是本局樓層計數；`Level 27` 才是樓層 id。
- 新樓層介紹後、`要走哪條路？` 前的那句白字是 `junction.text`，不是 `floor.intro`。

## 22. 事件本身造成樓層切換（沒有出口事件）

並非所有樓層切換都會先出現 `【出口的門】`、`【光】` 或 `出口進度`。

事件結果可以直接把玩家送到另一層。

### 22.1 實例：`【地上的洞】` → `Level 2.1「地下綜合體」`

```text
event.name = 地上的洞
event.intro =
地毯的正中央有一個圓圓的洞，邊緣很整齊，像是用尺畫出來的。往下看，什麼都看不到，丟一片碎紙下去，聽不到落地的聲音。
洞旁邊，有人用原子筆寫著：「許願池。一次一枚。」

action.selected =
→ 你決定：「丟一枚硬幣下去，許個願」

event.result =
……但接下來發生的事，誰也沒有料到。
硬幣掉下去之後，洞開始慢慢變大。地毯往洞裡滑，你也往洞裡滑——等你回過神來，四周已經是完全陌生的地方了。

event.result.effect.floorTransition = Level 2.1「地下綜合體」

system.transition =
(走出了這一層——這段路的記憶留了下來：你的記憶碎片 +5)
已經走過 6 層了——你：經驗 +6

floor.title = Level 2.1「地下綜合體」
floor.meta  = 第 7 層｜岔路
floor.header = —— Level 2.1「地下綜合體」——

floor.intro =
你從一面滾燙的牆裡跌出來，跌進一片昏暗的迷宮。牆、天花板、柱子全是水泥磚砌的，磚縫裡填著像水泥又像膠水的東西，怎麼摳都摳不動。
燈光很少：幾顆昏黃的小燈泡、幾盞骯髒兮兮的工業燈，偶爾還有插在牆上的火把。地上一半是泥土，一半是水泥，到處是鬆脫的鋼筋。
遠處有水滴聲，還有很低很低的機器嗡嗡聲——那個聲音，不管你怎麼走，都不會變近。

dialogue.player = 天狐：「火把的影子……好像多了一個……」

junction.text =
一條筆直的走廊，你走了五分鐘，走到了……剛才出發的地方。一個轉彎都沒有。

junction.prompt = 要走哪條路？
junction.paths = [
  { text: 走進那個天花板垂著一根根水泥柱的洞窟, perception: false },
  { text: 走進那條牆面特別粗糙的窄道, perception: false },
  {
    text: 跟著火把走,
    perception: true,
    hint: （只有你察覺到）你聽見那邊有很慢很慢的流水聲。,
    hintKind: 流水聲,
    announce: true
  }
]
```

### 22.2 規則

```text
event.kind = transition_event / floor_jump
event.result.causesFloorChange = true
event.result.nextFloor = Level 2.1「地下綜合體」
```

- 事件本身可以是樓層切換來源。
- **不強制**先有出口事件。
- 不一定要出現「出口進度」。
- 系統結算（記憶碎片、經驗）可以直接接在事件結果後。
- 新樓層從 `floor.header` 才開始；`event.result` 不是 `floor.intro`。

### 22.3 不可假設切層一定有提示

```text
樓層切換
  ├─ 出口事件（【出口的門】/【光】）
  └─ 事件結果直接切層（【地上的洞】）
```

Parser 不能只在看到出口事件時才準備切層；任何事件結果後都可能出現：

```text
system.transition
→ floor.header
```

### 22.4 小數樓層

```text
Level 2.1「地下綜合體」
```

不是 `Level 2` 的子事件，是一個獨立樓層 id：

```text
floor.id = 2.1
```

`第 7 層` 仍是本局樓層計數，不是 `Level 7`。

### 22.5 感知提示仍只記類型

```text
跟著火把走
（只有你察覺到）你聽見那邊有很慢很慢的流水聲。
```

只能記：

```text
path.perception = true
path.hint = 你聽見那邊有很慢很慢的流水聲
path.hintKind = 流水聲
```

不可自行補成「水相關事件」或某個事件名。

## 23. 戰鬥切入與高速取樣需求

### 23.1 戰鬥是路徑選擇的結果

畫面順序可能是：

```text
path.selected =
→ 你決定：「走進那個天花板垂著一根根水泥柱的洞窟」

combat.lead =
前面那盞工業燈，突然開始變亮。

combat.start =
【戰鬥】巨大的光附靈
```

戰鬥不是獨立憑空出現；它通常由**上一個路口選擇**觸發。

因此每場戰鬥都要嘗試記錄：

```text
combat.trigger.kind = path
combat.trigger.text = 走進那個天花板垂著一根根水泥柱的洞窟
combat.trigger.frame = 選擇時的 frame id
```

如果取樣漏掉那個路口，不能亂猜，要標：

```text
combat.trigger = unknown
combat.trigger.reason = text_missed
```

### 23.2 戰鬥畫面可讀出的欄位

```text
combat.enemy.name = 巨大的光附靈
combat.enemy.hp = 23/23
combat.enemy.defense = 14
combat.initiative = 巨大的光附靈 13 → 天狐 10
combat.round = 第 1 回合
```

戰鬥開場介紹：

```text
你一靠近那盞燈，燈就開始變亮——亮到刺眼、亮到發燙、亮到整條隧道只剩白色。燈裡面有東西。
光附靈是沒有怪東西的東西，它們附身在光源上，先用強光把人照得頭昏眼花，再發動攻擊。一般的攻擊很難傷到它。你注意到，它好像離不開有燈的地方。
巨大的光附靈：比一般的大上一圈
```

這是 `combat.intro`，不是樓層介紹。

戰鬥進入檢定：

```text
（魅力 難度 18）天狐 擲出 1+1=2 → 大失敗！ 理智 -6
```

分類：

```text
combat.entryCheck.attribute = 魅力
combat.entryCheck.outcome = failure
combat.entryCheck.effects = [{ kind: 理智, amount: -6 }]
```

同樣**不記錄實際難度與骰值**。

先攻順序：

```text
combat.initiative = 巨大的光附靈 13 → 天狐 10
```

敵人行動：

```text
（巨大的光附靈 灼燒 防禦 13）巨大的光附靈 從燈泡裡竄出一道熾熱的光，撲向 天狐：擲出 15+6=21 → 命中 天狐！ 體力 -7、理智 -2
```

分類：

```text
combat.enemyAction.name = 灼燒
combat.enemyAction.target = 天狐
combat.enemyAction.outcome = hit
combat.enemyAction.effects = [{ kind: 體力, amount: -7 }, { kind: 理智, amount: -2 }]
```

玩家行動面板：

```text
攻擊
技能
防禦／閃避
切換武器
使用物品
逃跑
```

分類：

```text
combat.playerActions[]
```

### 23.3 目前的取樣速度不足

目前的 `-Interval 0.8` 在實戰中約只有 1.2 FPS；戰鬥文字可能在一幀內閃過，造成：

- 看不到是哪個路口選項觸發戰鬥
- 戰鬥入場檢定被漏掉
- 敵人先攻、第一回合文字被截斷
- 結果與效果無法歸屬

### 23.4 必須加入的取樣策略

1. **平常提高取樣率**
   - 目標至少 2–4 FPS，必要時更高
   - 只做區域 OCR（main／opts／enemy／title），不要每幀整張 OCR

2. **戰鬥／轉場爆發取樣**
   - 偵測到 `【戰鬥】`、`要怎麼做？`、`要走哪條路？`、`出口進度`、`Level ???` 等錨點時
   - 立刻進入 burst：0.15–0.3 秒一張，持續 5–10 秒
   - burst 結束後回到一般取樣

3. **環形緩衝（pre-roll）**
   - 記憶體保留最近 N 張畫面／最近 N 次文字
   - 偵測到戰鬥後，回頭 OCR 戰鬥前幾幀
   - 用來補回「哪個路口選項觸發戰鬥」

4. **Last selected path**
   - 每次看到 `→ 你決定：「…」` 先更新 `lastSelected`
   - 若下一幀是 `【戰鬥】`，直接綁定：

```text
combat.trigger = lastSelected
```

5. **不確定就標 unknown**
   - 若 pre-roll 與 lastSelected 都沒有，記 `trigger=unknown`
   - 不要用「最可能的選項」猜

6. **截圖仍然只用來讀字**
   - burst 截圖只存在暫存
   - OCR 完成後刪除
   - 不進 Wiki

### 23.5 戰鬥與事件的關係

目前先分開建模：

```text
event
  └─ combat
       ├─ enemy
       ├─ entryCheck
       ├─ initiative
       ├─ rounds[]
       │    ├─ enemyAction
       │    └─ playerAction
       └─ result
```

戰鬥是否算一個「事件」、是否佔出口進度，目前**尚未由使用者確認**，不要自行寫入正式事件樹。

### 23.6 不可自行補的戰鬥資料

- 未看到的路口選項
- 未看到的敵人 HP／防禦
- 未看到的先攻順序
- 未看到的傷害數字
- 未看到的戰鬥結果

寧可缺，不要編。

## 24. 戰鬥撤退與戰後判定

這兩張圖是同一個戰鬥流程的後半：逃跑成功，回到路口。

### 24.1 戰鬥中的玩家行動

```text
combat.playerAction.kind = skill
combat.playerAction.name = 撤退路線
combat.playerAction.dialogue = 天狐：「論壇上說過，遇到這種要跑！往這邊！」
combat.playerAction.text = 天狐 指出了一條退路。
```

接著是撤退判定：

```text
combat.escape.check.attribute = 敏捷
combat.escape.check.outcome = success
combat.escape.result = 天狐 撤離了戰鬥。
```

不記：

```text
難度 9
9+9=18
```

### 24.2 戰鬥結束

```text
combat.result =
你一路狂奔，直到再也聽不見身後的聲音。
戰鬥結束了——你活了下來，但什麼也沒拿到。

combat.outcome = escaped
combat.loot = 無
```

### 24.3 戰後判定

戰鬥結束後還可能出現額外判定：

```text
combat.aftermathCheck.attribute = 智力
combat.aftermathCheck.outcome = success
combat.aftermathCheck.text =
天狐 皺起眉頭：「剛才光附靈的動作……好像有什麼規律，可是還抓不太到。下次再遇到，要仔細看。」
combat.aftermathCheck.flag = 下次再遇到也許就想得通
```

這不是事件行動，也不是戰鬥攻擊；是**戰後觀察／情報判定**。

### 24.4 戰鬥後回到路口

```text
combat.completed
→ floor.progress = 1/8
→ 新路口
```

新路口：

```text
floor.progress = 1/8

statusEffect =
天狐 渴得嘴唇乾裂，眼前一陣陣發黑。體力 -1、理智 -1

junction.text =
一根比較冷的管子貼著天花板經過，管子上凝結著一顆顆水珠，聞起來是杏仁的味道。

dialogue.player =
天狐：「我、我還可以……只是流了一點血。」

junction.prompt = 要走哪條路？
junction.paths = [
  { text: 穿過滿是岩石陰影的洞窟, perception: false },
  { text: 往機器聲的方向走, perception: false }
]
```

### 24.5 戰鬥與出口進度的關係

截圖顯示戰鬥撤退後出現：

```text
出口進度 1/8
```

但「戰鬥是否算一個事件、是否一定佔出口進度」目前**尚未由使用者確認**。

先保留：

```text
floor.progress.current = 1
floor.progress.total = 8
floor.progress.source = unknown（可能是戰鬥／路線事件）
```

不要自行寫成「戰鬥一定算事件」。

### 24.6 狀態效果

```text
天狐 渴得嘴唇乾裂，眼前一陣陣發黑。體力 -1、理智 -1
```

分類：

```text
statusEffect.target = 天狐
statusEffect.reason = 口渴／脫水
statusEffect.effects = [
  { kind: 體力, amount: -1 },
  { kind: 理智, amount: -1 }
]
```

不可併進戰鬥傷害，也不可當成普通 dialogue。

### 24.7 高速取樣補充

這一串文字全部可能在幾秒內閃過：

```text
使用撤退路線
角色台詞
指出退路
敏捷判定
撤離戰鬥
戰鬥結束
智力判定
戰後台詞
狀態效果
出口進度
新路口文字
```

所以 pre-roll + burst 必須覆蓋**戰鬥結束後 5–10 秒**，不能只在看到 `【戰鬥】` 時開始；否則會漏掉戰後判定與出口進度。

## 25. 已確認：戰鬥算一個戰鬥事件

使用者確認：

> 算一個戰鬥事件。

因此戰鬥不是獨立於事件之外的東西，而是 `event` 的一種類型。

### 25.1 戰鬥事件模型

```text
event.kind = combat
event.header = 【戰鬥】巨大的光附靈
event.name = 巨大的光附靈

event.trigger =
  kind: path
  text: 走進那個天花板垂著一根根水泥柱的洞窟

combat = {
  enemy: {
    name: 巨大的光附靈,
    hp: 23/23,
    defense: 14,
    trait: 比一般的大上一圈
  },
  intro: ...,
  entryCheck: { attribute: 魅力, outcome: failure, effects: [...] },
  initiative: 巨大的光附靈 13 → 天狐 10,
  rounds: [...],
  playerAction: 撤退路線,
  escapeCheck: { attribute: 敏捷, outcome: success },
  result: 戰鬥結束了——你活了下來，但什麼也沒拿到。,
  outcome: escaped,
  aftermathCheck: { attribute: 智力, outcome: success, flag: ... }
}
```

### 25.2 戰鬥事件佔一個事件進度

戰鬥事件完成後：

```text
event.completed
→ floor.progress.current += 1
```

例：

```text
戰鬥事件【巨大的光附靈】完成
→ 出口進度 1/8
```

所以之前截圖的 `出口進度 1/8` 可以確定：

```text
floor.progress.source = combat_event
```

不是未知來源。

### 25.3 戰鬥事件的完成時機

一場戰鬥 = 一個事件，不是每一回合一個事件。

完成時機是整場戰鬥結束：

```text
勝利
或
成功撤退
```

戰後判定（例如智力觀察）仍屬於同一場戰鬥事件，不另開新事件。

```text
combat.result
→ combat.aftermathCheck
→ event.completed
→ floor.progress +1
→ 下一個路口
```

### 25.4 戰鬥事件與普通事件的差異

| 項目 | 普通事件 | 戰鬥事件 |
|---|---|---|
| event.kind | normal | combat |
| 名稱來源 | `【事件名】` | `【戰鬥】敵人名` |
| 內容 | intro / actions | enemy / combat rounds |
| 完成 | 看完按繼續 | 勝利或撤退 |
| 進度 | +1 | +1 |
| 戰後判定 | 不一定 | 可有，仍屬同一事件 |

### 25.5 不可拆分

不可把以下拆成多個事件：

```text
路口選項
戰鬥開始
第 1 回合
第 2 回合
撤退
戰後判定
```

它們全部屬於**同一個戰鬥事件**：

```text
event.kind = combat
```

### 25.6 仍需保留的關聯

```text
event.trigger.path
event.trigger.frame
event.completed
floor.progress
```

即使戰鬥文字閃得很快，也要靠 pre-roll / lastSelected 把「哪個路口觸發這場戰鬥」補回來。

## 26. 第二場戰鬥事件：`【戰鬥】微笑夢魘`

### 26.1 入口

```text
path.selected =
→ 你決定：「往機器聲的方向走」

path.result / combat.lead =
你避開了所有的燈——黑暗裡，浮出一排牙齒。

event.kind = combat
event.header = 【戰鬥】微笑夢魘
event.name = 微笑夢魘
```

`path.result` 是戰鬥前最後一句路徑結果；不要把它併進戰鬥介紹。

### 26.2 敵人資料

```text
combat.enemy.name = 微笑夢魘
combat.enemy.hp = 16/16
combat.enemy.defense = 13

combat.enemy.intro =
黑暗中浮出一排發光的牙齒和一雙眼睛，咧成不可能的弧度。它的身體是一團漆黑的、像火焰一樣的東西，物理攻擊幾乎傷不了它。
但它有兩個弱點：光和火。被光照到，它會痛得縮起來；著了火，它會慢慢被燒光。只是有些微笑夢魘特別能忍痛。

combat.enemy.weaknesses = [光, 火]
combat.enemy.resistances = [物理]
combat.enemy.note = 有些個體特別能忍痛
```

弱點／抗性要獨立欄位，不能只留在介紹文字裡。

### 26.3 入場檢定

```text
combat.entryCheck.attribute = 魅力
combat.entryCheck.outcome = failure
combat.entryCheck.effects = [
  { kind: 理智, amount: -4 }
]
```

不記：

```text
難度 19
7+1=8
```

### 26.4 先攻順序

```text
combat.initiative = 天狐 22 → 微笑夢魘 19
```

這場玩家先攻；先攻順序要保留方向。

### 26.5 玩家行動面板

```text
combat.playerActions = [
  攻擊（右手：拳頭，傷害 1d2+1 鈍擊，力量）,
  技能（撤退路線、緊急處置）,
  防禦／閃避,
  切換武器（背包裡沒有其他武器）,
  使用物品（背包裡有 1 個消耗品）,
  逃跑（敏捷檢定，難度 variable，加成 +6；成功脫離戰鬥，拿不到戰利品）
]
```

這些是**可選行動**，不是已選行動；不要記成玩家已使用。

### 26.6 系統聊天訊息

右下角：

```text
系統：遊戲有新版本了！這一局玩完之後，重新整理網頁就會更新
（舊版 3 天內照樣拿得到記憶碎片）。
```

這是**系統 UI／公告**，不是戰鬥事件，也不是玩家台詞。

```text
system.announcement
→ 可保留 raw
→ 不進事件樹
```

### 26.7 戰鬥事件完成

戰鬥勝利或成功撤退後：

```text
combat.result
→ combat.aftermathCheck（若有）
→ event.kind = combat
→ event.completed
→ floor.progress.current += 1
```

這場戰鬥應占本層一個事件進度；截圖沒有顯示完成後的 `出口進度`，所以不要在沒有畫面證據時寫出實際 `N/8` 數字。

## 27. 結局／死亡流程（`全员迷失` / `全员逃离`）

這一組圖不是普通事件，而是**本局結束**。

### 27.1 先出現戰鬥致死

```text
combat.damage =
命中 天狐！ 體力 -5、理智 -3

combat.defeat =
天狐 一直盯著黑暗裡那排牙齒，盯到自己的嘴角也跟著慢慢往上彎……天狐 迷失了。
```

分類：

```text
combat.playerDefeated = true
run.outcome = missing
```

這場戰鬥事件到這裡不會再回到普通路口，而是進入結局流程。

### 27.2 結局幻燈片

畫面：

```text
全員逃離 / 全員迷失（原始標籤，依畫面照抄）
Level 2.1

機器的嗡嗡聲還在遠處，一點都沒有變近。濕水泥河緩緩流過，把你留下的痕跡一點一點抹平。
```

第二張：

```text
後室不會記得任何人。
可是在「Level 2.1」的某個角落，有幾個名字被很用力地刻進了牆裡。每一個經過的人都會停下來看一眼，然後說：「他們走到這裡了。」
```

分類：

```text
ending.kind = escape | missing | ...
ending.labelRaw = 畫面上的原始標籤
ending.floorId = Level 2.1
ending.slides[] = [
  { text: ... },
  { text: ... }
]
```

規則：

- 這是結局文本，不是 `floor.intro`
- `ending.labelRaw` 要保留畫面原文
- 若同一局不同畫面出現不同標籤（例如 `全員逃離` / `全員迷失`），先保留兩個 raw，不要自行合併
- `跳過` 是 UI，不是結局正文

### 27.3 角色墓誌／最後訊息

```text
天狐
諾亞｜熬夜的高中生（倒下了，被大家帶著走到最後）

天狐 在論壇上的最後一篇文，停在一句話：「我、我們好像走錯了——」
底下有人回覆：「這是創作吧？」
```

分類：

```text
ending.epitaph.character = 天狐
ending.epitaph.characterTitle = 諾亞｜熬夜的高中生
ending.epitaph.endState = 倒下了，被大家帶著走到最後
ending.epitaph.lastPost = 我、我們好像走錯了——
ending.epitaph.reply = 這是創作吧？
```

這不是普通 `dialogue.player`；是結局角色卡／墓誌。

### 27.4 本局統計與獎勵

```text
【你迷失】
後室不會記得任何人。
可是在「Level 2.1」的某個角落……

天狐：「論、論壇上……沒寫這一段……」

【這一局的稱號】
天狐：最常帶頭（當了 13 次主角）

（走過 28 個地方、打倒 0 個東西 +8、事件和委託留下的記憶 +1、走出的每一層 +17（倒下的人也有））
這次冒險留下了記憶碎片：還站著的人 26 片，倒下或迷失的人 21 片。
這一趟一共走過 6 個不同的層。（排行榜算的是這個：重複走進同一層不會多算）
```

分類：

```text
run.title = 最常帶頭
run.titleDetail = 當了 13 次主角
run.stats.placesVisited = 28
run.stats.enemiesDefeated = 0
run.stats.extra = +8
run.stats.eventMemory = +1
run.stats.floors = +17
run.memoryShards.standing = 26
run.memoryShards.fallen = 21
run.distinctFloors = 6
```

「走過 7 層」和「6 個不同的層」要分開：

```text
run.floorsEntered = 7        // 走過 7 層，可能含重複
run.distinctFloors = 6       // 排行榜用不重複樓層
```

### 27.5 冒險結束卡

```text
冒險結束。
全員迷失
最後抵達：Level 2.1「地下綜合體」，走過 7 層
你得到了 21 片記憶碎片（現在共有 751 片）
```

分類：

```text
ending.summary.outcome = 全員迷失
ending.summary.finalFloor = Level 2.1「地下綜合體」
ending.summary.floorsEntered = 7
ending.reward.memoryShards = 21
ending.wallet.memoryShards = 751
```

按鈕：

```text
再看一次結局
回到大廳，再來一局
```

是 UI，不進結局正文。

### 27.6 標籤不一致時

這組圖中：

- 結局幻燈片標籤看起來是 `全員逃離`
- 冒險結束卡是 `全員迷失`
- 戰鬥日誌是 `天狐 迷失了`
- 死亡文字是 `【你迷失】`

先全部保留 raw：

```text
ending.labelSlide = ...
ending.labelSummary = ...
run.playerOutcome = missing
```

在確認之前，不要自行統一成單一結局名稱。

### 27.7 結局與戰鬥事件的關係

流程：

```text
combat event
  → 玩家被擊倒／迷失
  → combat.playerDefeated
  → ending.trigger
  → ending.slides
  → ending.epitaph
  → ending.summary
  → 回到大廳 / 再看一次結局
```

戰鬥事件仍然是戰鬥事件；但玩家死亡時，它同時是**本局結束的觸發點**。

```text
event.kind = combat
event.completed = false
event.outcome = player_defeated
run.ending = missing
```

不要把它記成普通戰鬥勝利，也不要再記 `floor.progress +1`。
