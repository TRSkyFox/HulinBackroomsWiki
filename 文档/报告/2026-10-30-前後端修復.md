## 1. 事件解析：檢定與結果

### 修了什麼

`event-parse.mjs` 原本只認帶括號的 `（力量 檢定）`，但遊戲實際輸出是：

```
你魅力难度12
```

沒有括號 → `check` 永遠是 `null`。另外「你決定：「…」」比對不到選項文字時（OCR 把「坐下来」讀成「坐下采」）整個放棄 → 後面的結果全部丟掉。

### 現在的數字

| | 修前 | 修後 |
|---|---|---|
| 有檢定（屬性＋難度） | 6 / 61 | **18 / 61** |
| 有結果 | 26 / 61 | **56 / 61** |
| 有效果（體力/理智/經驗） | — | 30 |

舊場次是用 `_backfill` 一次性重跑補的（16 個場次全部重跑 `event-parse`，再按事件名合併，只做加法不覆蓋正文）。匹配時要先過管線的 `text()`（簡→繁），否則 OCR 簡體名對不上 wiki 繁體名 —— 一開始 57/61 對不上就是這個原因。

### 殘渣清理

合併進來的結果會帶「決定：！坐下采…」這種選擇回顯與 intro 碎片。已加：

- `isDecision` 認 `決定：`／`：！…`（OCR 吃掉「你」也擋）
- 結果入庫前過 `cleanResults`
- 一次性清理腳本移除 7 條回顯、3 條碎片

## 2. 記錄器：靜止畫面壓縮

### 問題

那場 8 小時 11 分鐘停在主選單的錄製：

```
35,618 幀 → structured.jsonl 152 MB
         → ocr-raw.log        45 MB
```

同一個畫面被寫了三萬多次。

### 改法

- `structured.jsonl`：連續相同且 `layout=normal` 的幀只寫一筆區間
  `{"frame":2,"dupTo":90,"dup":89,"lines":[]}`
- `ocr-raw.log`：同樣情況整段跳過不寫
- 收工時補寫未關閉的區間；結束日誌多印「其中 N 幀與上一幀相同、已合併成區間」

### 驗證

```
單測（10 幀：1 正常 + 8 靜止 + 1 正常）
  舊：1401 bytes
  新： 439 bytes（省 69%；真實幀 4.5KB 時省 99%）
下游：parse.mjs / event-parse.mjs 對 dup 記錄（lines: []）正常，仍能認出樓層
```

⚠️ **端到端還沒在真實遊玩中驗證** —— 記錄器有「目標不在前景就暫停」的保護，測試窗口搶不到前台。下次真的玩一局看 `logger.log` 那行就知道。

## 3. 配色：取樣點錯了

`Get-MainFillColor` 掃的是 **main 面板內側**（卡片色），Wiki 要的是**牆色**。而且 `floor-colors.log` 的解析正則跟實際格式對不上（要 `樓層：Level … 配色=#…`，實際是 `#4B4424 rgb(...) Level 0 「大厅」`）→ 那段 fallback 從來沒生效。

### 三處改動

1. 記錄器新量「牆色」：掃畫面四邊窄條取眾數，寫進 `floor-colors.log`
2. `import-wiki` 優先採用牆色；截圖配色只有在跟牆色接近（距離 ≤ 40）時才沿用卡片/強調色
3. 近黑/近白一律剔除（亮度 < 0.04 或 > 0.94）

### 套用端也修了

`setFloor()` 以前只寫 `bg/card/line/acc/tx` 五個變數，其餘 `--bg2/--card2/--line2/--acc2/--tx2/--tx3` **沿用上一層或預設**。現在五個主色寫完，其餘全部推導；並在套用前做健康檢查：

```
line 太亮（取到文字像素）→ 用 card 推導
文字對比 < 3.6          → 往白/黑推
底色太亮、白字也到不了 3.2 → 先把底色壓暗一級
```

修完 14 層的對比全部 ≥ 3.6（原本最低 1.55）。
