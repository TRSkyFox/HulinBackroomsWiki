## 1. 事件解析：检定与结果

### 修了什么

`event-parse.mjs` 原本只认带括号的 `（力量 检定）`，但游戏实际输出是：

```
你魅力难度12
```

没有括号 → `check` 永远是 `null`。另外“你决定：“…””比对不到选项文字时（OCR 把“坐下来”读成“坐下采”）整个放弃 → 后面的结果全部丢掉。

### 现在的数字

| | 修前 | 修后 |
|---|---|---|
| 有检定（属性＋难度） | 6 / 61 | **18 / 61** |
| 有结果 | 26 / 61 | **56 / 61** |
| 有效果（体力/理智/经验） | — | 30 |

旧场次是用 `_backfill` 一次性重跑补的（16 个场次全部重跑 `event-parse`，再按事件名合并，只做加法不覆盖正文）。匹配时要先过管线的 `text()`（简→繁），否则 OCR 简体名对不上 wiki 繁体名 —— 一开始 57/61 对不上就是这个原因。

### 残渣清理

合并进来的结果会带“决定：！坐下采…”这种选择回显与 intro 碎片。已加：

- `isDecision` 认 `决定：`／`：！…`（OCR 吃掉“你”也挡）
- 结果入库前过 `cleanResults`
- 一次性清理脚本移除 7 条回显、3 条碎片

## 2. 记录器：静止画面压缩

### 问题

那场 8 小时 11 分钟停在主菜单的录制：

```
35,618 帧 → structured.jsonl 152 MB
         → ocr-raw.log        45 MB
```

同一个画面被写了三万多次。

### 改法

- `structured.jsonl`：连续相同且 `layout=normal` 的帧只写一笔区间
  `{"frame":2,"dupTo":90,"dup":89,"lines":[]}`
- `ocr-raw.log`：同样情况整段跳过不写
- 收工时补写未关闭的区间；结束日志多印“其中 N 帧与上一帧相同、已合并成区间”

### 验证

```
单测（10 帧：1 正常 + 8 静止 + 1 正常）
  旧：1401 bytes
  新： 439 bytes（省 69%；真实帧 4.5KB 时省 99%）
下游：parse.mjs / event-parse.mjs 对 dup 记录（lines: []）正常，仍能认出楼层
```

⚠️ **端到端还没在真实游玩中验证** —— 记录器有“目标不在前景就暂停”的保护，测试窗口抢不到前台。下次真的玩一局看 `logger.log` 那行就知道。

## 3. 配色：取样点错了

`Get-MainFillColor` 扫的是 **main 面板内侧**（卡片色），Wiki 要的是**墙色**。而且 `floor-colors.log` 的解析正则跟实际格式对不上（要 `樓層：Level … 配色=#…`，实际是 `#4B4424 rgb(...) Level 0 「大厅」`）→ 那段 fallback 从来没生效。

### 三处改动

1. 记录器新量“墙色”：扫画面四边窄条取众数，写进 `floor-colors.log`
2. `import-wiki` 优先采用墙色；截图配色只有在跟墙色接近（距离 ≤ 40）时才沿用卡片/强调色
3. 近黑/近白一律剔除（亮度 < 0.04 或 > 0.94）

### 套用端也修了

`setFloor()` 以前只写 `bg/card/line/acc/tx` 五个变数，其余 `--bg2/--card2/--line2/--acc2/--tx2/--tx3` **沿用上一层或默认**。现在五个主色写完，其余全部推导；并在套用前做健康检查：

```
line 太亮（取到文字像素）→ 用 card 推导
文字对比 < 3.6          → 往白/黑推
底色太亮、白字也到不了 3.2 → 先把底色压暗一级
```

修完 14 层的对比全部 ≥ 3.6（原本最低 1.55）。
